# topology：连接图与指定割集

候选实现 `graph.py`、`builders.py`；未实现，见 [STATUS](../../docs/STATUS.md)。图只拥有身份和连接关系，引用 links、switches 和公共端点；没有额外带宽、能量或队列。

| 字段/量 | 角色/单位 | 含义与约束 |
| --- | --- | --- |
| endpoint_specs / switch_ports | 输入；不可变集合 | 网络边界与交换端口，node/owner/port 唯一 |
| directed_links | 输入；LinkParams tuple | 有向物理通道；全双工反向边必须显式提供 |
| internal_connections | 输入/派生；端口关系 | 交换入口到允许出口的可达关系，绑定内部共享资源；不额外计外部链路 hop |
| bandwidth_constraints | 输入；资源引用 | 容量和字节基准一致；同资源不同容量声明必须拒绝 |
| cut_vertex_ids | 每次输入；设备顶点集合 | 调用者指定节点NIC边界/完整交换机的切分S，展开其全部端口；首批不切割交换机内部，也不自动求最小割或二分割 |
| outgoing_cut_links / cut_capacity_Bps | 派生；边集合、B/s | S到外部的独立有向容量和，基准一致；反向单独计算 |
| reachable / diagnostics | 结果；bool/诊断 | 按方向及内部可转发关系检查，不从节点数推断可达 |

首批校验物理端口的出/入方向占用：一对全双工边合法，多条独立连接需多个明确物理端口；共享介质必须有显式资源约束，不能靠重复端口偷偷增容量。所有权树无环，网络图允许环。

路径检查包含“外链路到达交换入口 → 允许的内部转发 → 下一外链路离开”；不同物理端口不能仅因属于同一节点就自动相连。终端不转发中间流量。直连图可以在交换模型实现前独立构建。

`validate_graph` → 可达性查询/指定割查询 → 由 routing 选路；topology 不反向调用 routing。builders 只生成相同数据结构，先支持直连、单交换机、两分区夹具；复杂拓扑按实验需要扩展。

割容量 `B_cut=ΣB_e` 仅为链路容量和；共享 NIC/交换内部约束另算，不能因此宣称所有边可同时满速。指定割没有边且无需求时返回零；存在跨割需求则不可行。参数敏感性集中在方向、连接层级和共享上行。

验证：重复/悬空引用、端口所有权、双工、断网、合法环、交换内部连接、手工与 builder 同图、指定割逐方向手算。依据 [M06](../../docs/methods/parameters_and_math.md)、[设计](../docs/design.md)；无通用图优化或网络实测覆盖。
