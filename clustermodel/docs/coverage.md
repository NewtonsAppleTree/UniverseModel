# clustermodel 能力覆盖与开发次序

本轮已按用户要求完成**整体覆盖和可组合边界复核，再优化具体实现**。依据[项目使命](../../PROJECT_MISSION.md)与[架构参数清单](../../ARCHITECTURE_PARAMETERS.md)第6节。下表基础范围已经逐项落实；C1–C3、横向能力和收尾验证共同构成本轮交付，见[完成报告](completion.md)。更高精度的研究扩展按表中责任归属与证据条件进入。

## 1 覆盖矩阵

| 维度与研究问题 | 基础能力及本批横向工作 | 责任边界与后续深度 |
| --- | --- | --- |
| 资源与所有权：异构节点、多NIC/多端口是否共享真实容量 | 唯一node/endpoint/port/resource；多个rank和端口可引用同一NIC；完整资源图可独立构建 | 节点内部算力、内存、DMA和本地通信由systemmodel提供摘要；集群不得重新生成这些成本 |
| 物理组织：节点怎样跨交换层级互连 | 直连、单交换、两分区；本批补可变leaf/spine数量的构图函数，允许非均匀端点分区、多轨端点 | 手工有向端口图支持其他网络；更大Clos、dragonfly、光交换等按连接/控制机制需要加入，不能只按名字建空类 |
| 带宽表示：协议、方向和共享如何计数 | raw_line/effective_payload、帧格式、尾包、独立方向、显式共享介质、交换内部容量 | 协议版本与校准来源显式给定；包缓存、FEC重试、credit和窗口另建有依据模型 |
| 路径选择：可达性、等长多路径和路径固定性 | 显式路径、确定性最少hop；本批补最短路径总数与有界候选枚举 | 候选可显式传入分析；候选数量不等于独立带宽。ECMP散列、自适应分流、收敛时间属于后续策略/执行 |
| 逻辑组织：rank和通信组怎样映射 | 有序组、组间重叠、多rank共享NIC，逐消息检查成员 | 放置搜索和并行策略由compiler/evaluation处理，组名不自动展开通信算法 |
| 需求覆盖：流量由谁产生、流向哪里 | 固定P2P表达incast、outcast、矩阵型交换和多个组；本批补rank/节点/端点/声明组及节点间流量矩阵 | 这只是逻辑需求描述；collective数值、训练/推理任务生成由workloads/compiler/runtime提供 |
| 可行性与观测：断开的哪些端点会影响任务 | 图/路径/组/profile校验；本批补拓扑库存与指定源的方向可达性，失败候选继续留档 | 物理连通、可转发、消息可服务和完整任务正确性分别检验；不以一次运行成功代替所有层面的证明 |
| 性能分析：必要服务瓶颈来自哪里 | 逐消息/链路/NIC/交换/共享约束账本，资源/必要延迟/指定割的条件下界 | 排队、任务依赖、计算通信重叠、实际完成/可见性须事件模型；当前不输出伪造利用率 |
| 可用性：丢失某方向、节点或交换路径会怎样 | 本批补不可变静态停用视图，保留原图和停用来源；重新查询可达性与固定/重选路径 | 静态场景不模拟故障发现、修复、协议收敛、重传或概率可靠性；不会把不可达流量删掉 |
| 能量、成本与物理约束：收益是否可实现 | 来源、容量kind、profile域和未知成本显式记录 | J/bit、漏电、布线/端口预算、功率/热、硬件测量通过costmodel及外部证据接入，未知不能填0 |
| 实验与探索：比较是否公平、能否回读 | 固定图/输入的有限放置对照；本批将停用条件和流量/拓扑总览保存到同一记录 | 不同图/停用条件不可混成同预算放置结论；搜索预算、外部校准和统计比较由evaluation承担 |
| 验证与规模：典型和退化场景是否都有证据 | 手算、守恒、共享反例、异构profile、显式环、空输入；本批补leaf-spine冗余、方向停用、多轨共享和矩阵守恒 | 纯分析测试不证明真实吞吐；扩大规模时另量化宿主耗时/内存，不能归入目标系统时间 |

每项当前可运行状态和测试数量由[STATUS](../../docs/STATUS.md)维护；本表解释覆盖与边界，不把后续能力列为已经实现。

## 2 先广度、再深度的实施顺序

1. **边界与覆盖。** 用本表复核资源、拓扑、策略、工作量、观测、可用性、成本和实验链，不遗漏相邻模块接口。
2. **横向可运行入口。** 优先补leaf-spine构图、最短路径候选、静态停用/可达性视图、流量总览；复用现有图、P2P、账本及记录边界。
3. **跨场景验收。** 同时检查非均匀分区、多NIC共享、两个spine的路径冗余、方向故障、不可达、组重叠及流量矩阵守恒。保留已有四节点和C1证据。
4. **按证据缺口加深。** 如果问题是拥塞/尾延迟，则深化有限buffer、窗口和事件语义；如果是放置，则深化真实消息分布和路径选择；如果是物理收益，则先补校准来源及误差。每次都明确新增机制能检验什么。

基础范围复核和收尾优化已完成。下一轮开发chipmodel；本表中的事件、任务质量和物理校准扩展由具体课题触发，不作为切换模块的未完成基础事项。
