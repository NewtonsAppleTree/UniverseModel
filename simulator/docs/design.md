# simulator：统一时间、因果与观测

## 核心与装配

最重要的是事件按可解释的因果顺序发生。simulator 只依赖 contracts，接受 evaluation 注入的硬件组件、runtime 策略和观察器。`engine/events` 管事件队列，`engine/time` 管时间，`adapters` 适配协议，`stats` 管计数，`trace` 管轨迹，`snapshots` 管未来的完整检查点。

全局时间、待处理事件和稳定排序序号属于引擎。资源局部队列/占用属于组件，软件策略状态属于 runtime。统计可以订阅事件或组件计数器，但同一指标必须有唯一权威来源。

## 输入输出与时间契约

输入为冻结实验标识、执行计划、组件集合、初态和时间配置。输出 SimulationResult、输出引用、核心计数器、终止诊断和可选 TraceEvent。目标时间与宿主 wall time 使用不同字段。

时间参数包括 time unit/resolution、clock domains、event ordering、最大事件数、目标时间上限与墙钟超时。整数 tick 或精确有理表示可避免不稳定浮点比较；精度与舍入必须声明。多时钟下不能直接比较未标域的 cycle 数。

## 执行循环与数学

取最早事件 → 推进全局时间 → 处理完成/释放 → 更新可见性和依赖 → 调用策略 → 组件仲裁并预约新事件 → 更新独立计数器。相同时间按固定 phase/sequence 顺序，零时间事件级联需检测无进展。

资源服务时间来自组件与成本接口，排队由请求竞争自然产生。M06 给出时间下界，M07 用于检查队列数量级。实际事件结果违反有效下界时，先检查计量边界、遗漏资源或错误单位，不能用修正系数掩盖。

## 精度与扩展策略

功能模式可只执行数据效果；解析模式用于筛选；事件模式捕获有限资源；逐周期模型只细化必要组件。混用模型时明确事件同步与计费边界。大量同质操作可聚合为复合事件，但必须保留共享资源需求、可见性和允许重叠，不能只把时长相加。

性能优化包括事件批量处理、稀疏观测和缓存纯估计。任何加速都需保持目标结果和确定性。并行离散仿真、回滚和 checkpoint 恢复暂不作为首版前提。

## 验证与持久化

校验时间不倒退、请求不重复完成、依赖不提前满足、容量不超限；覆盖同时间完成、空队列未完成、取消及复位。全部必需操作完成且输出可见才成功。未完成且没有可推进事件时生成等待图/阻塞链诊断。

轨迹关闭或采样不能改变模拟结果，核心计数器不从采样轨迹反推。检查点必须同时保存事件、组件、runtime 和随机状态；保存版本不兼容时拒绝恢复。产物格式由 artifacts 负责，仿真器只生成语义内容。
