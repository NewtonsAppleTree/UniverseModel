# costmodel：动作成本与适用条件

## 核心与解耦

最重要的是成本有条件、有边界、有依据。costmodel 依赖 contracts，以动作和工作条件为输入，返回 `Estimate`；它不推进时间、不维护资源队列，也不替 runtime 作调度决定。

`providers/analytical` 放公式模型，`tabulated` 放特征化数据适配，`external` 包装外部工具；`interfaces` 定义调用面，`uncertainty` 表达范围与相关性。外部工具通过导出/适配接入，不侵入 chipmodel 的状态机。

## 输入、参数与输出

| 输入 | 关键参数 | 输出约束 |
| --- | --- | --- |
| ComputeAction | 操作、位宽、形状、活动量、V/f/T、机制 | 服务延迟、II 或动作能量，明确含哪些外围 |
| MemoryAction | 读写、字节/行、bank、命中层级、介质 | 服务需求、能量、访问粒度 |
| TransferAction | 字节数、距离、宽度、协议、封装技术 | 每跳/端到端范围，避免重复算控制器 |
| PhysicalInstance | 容量、端口、工艺、几何 | 面积、泄漏和热参数，不能按动作重复累计 |

每个 Estimate 返回单位、点值或区间、provider/version、来源、适用域、覆盖的成本项和外推标志。未知估计返回 unavailable 与原因，不能以零替代。没有概率模型时区间是情景范围，不称为置信区间。

## 计算链与边界

基础链为结构/动作描述 → 条件匹配 → 公式或查表/插值 → 量纲与范围验证 → 附来源返回。组件将服务需求转换为受资源约束的实际完成时间；排队等待不再作为固有单次动作成本反复叠加。

动作能量与泄漏积分采用 M11，面积采用 M12，CIM 转换阶段采用 M08。数字动态能量对电容和电压敏感，但通用 `C·V²` 只支持趋势推断，不能替代具体实现校准。延迟与电压/温度也不能假定全域线性。

查询缓存键必须包含结构、动作、工作条件、模型版本和误差模型。把一组芯片条件下的能量常数复用于不同工艺/精度需明确假设与误差。

## 校准与模型选择

早期解析估计用于筛选；公开工具、特征化表和实测逐步缩小误差。CACTI、Accelergy、NeuroSim、Ramulator 等覆盖对象不同，不直接把输出拼成“准确芯片”。先对齐动作定义、工艺、容量、外围与统计边界，再组合。

拟合训练集与验证集分离；同时保存残差和未建模行为。范围外请求可拒绝、切换模型或显式外推，策略由实验配置决定。涉及共享工艺或电压的参数误差可能相关，不能默认独立采样。

## 验证与证据

验证量纲、来源点再现、插值连续性和适用域处理；检查每次动作和每个实体各只收费一次。只在物理合理范围内使用单调性检查，因为端口数、bank 数和控制开销可能使趋势变化。

保存成本 manifest、参数数据哈希、工具版本、调用条件和不确定性说明。研究结果若在成本区间内排名翻转，应输出“需补充校准”，不能只保留最好点值。

## 成本覆盖与可识别性

Estimate 附覆盖范围与未知项，部分成本不能作为完整总成本；摘要与明细的唯一计入方见[组合规则](../../docs/architecture/model_composition.md)。拟合前判断观测是否足以区分参数，例如一个消息大小的总延迟无法同时识别启动与带宽；实验设计见[有效性规范](../../docs/methods/experiment_validity.md)。
