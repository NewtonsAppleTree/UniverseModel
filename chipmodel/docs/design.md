# chipmodel：计算、存储、互连与封装

## 核心与层级

最重要的是数据与计算能否在有限资源上合法发生。chipmodel 依赖 contracts、costmodel，拥有芯片与封装内部的资源状态；只包含软件模型。Core/Tile/Die/Package 通过组合建立实例，不能由目录数量推定硬件数量。

| 子系统 | 关键参数 | 独占状态 |
| --- | --- | --- |
| compute/cpu | 核数、ISA/操作能力、issue width、缓存/执行摘要 | 发射与执行资源；细模型可含流水线 |
| compute/gpu | SM 数、warp、执行宽度、寄存器/shared memory | 活跃任务、资源配额、访存等待 |
| compute/npu | PE/MAC 数、数据流、切块能力、局部缓冲 | 阵列占用、累加状态、输入输出队列 |
| compute/cim | rows/columns/layers、cell bits、编码、外围共享 | 权重映射、编程状态、转换/累加资源 |
| memory | 介质、容量、bank、端口、粒度、时序 | 内容版本、队列、行/bank 状态 |
| interconnect | NoC/D2D 拓扑、带宽、延迟、路由、缓冲 | 链路与路由器占用、背压 |
| control | 队列、同步、仲裁、发射能力 | 就绪、控制请求与硬件同步 |
| composition / packaging | 物理组成、连接技术、几何、热/供电域 | 组合引用；热模型拥有温度状态 |

CPU/GPU 可先用能力与服务摘要模型，研究微架构时再细化。摘要设备与内部细模型是替代层级，不能双重执行。NPU 的 engine_kind 与 compute_mechanism 分开：一个 NPU 可以混合数字 MAC 和 CIM。

## 输入输出与责任

输入是冻结结构、成本接口和显式请求；输出是 HardwareSpec 能力、接受/背压、完成/失败、动作计数及只读观测。每个组件维护自己的容量、队列、数据和状态；simulator 提供时间与事件接口。compiler 不能直接改存储内容或队列。

传输必须经过有效端口及路径，声明内存读、链路、目标写阶段的计时边界。地址域与一致性是能力，不能因为两个资源同属一个 Package 就视为共享一致内存。

## CIM 与 3D CIM 的特有链条

模拟 CIM 链为量化/编码 → 权重位切片与写入 → 输入 DAC/脉冲 → 阵列求和 → ADC → 移位累加 → 输出变换。数字 CIM 可没有 ADC/DAC，应按实际机制选择阶段。权重写入、校准、ADC 共享和阵列外累加都可能成为瓶颈。

分别描述阵列物理容量、有效权重容量和每次计算活跃规模。正负差分、位切片、冗余、坏单元及元数据会降低有效容量。使用 M02/M08 推导，不能以物理 bit 数直接换算为吞吐。

3D 有三种组合：阵列内增加层数；多个 CIM Die 垂直互连；CIM Die 与逻辑 Die 堆叠。层选择、垂直带宽、ADC 放置、compute_die_count、热阻和权重写入路径分别建模。层数增长不保证并行度等比例增长。

## 参数依赖与工作流

工作量/精度 → 映射后的 tile 与流量 → 存储容量/端口合法性 → 引擎和外围服务需求 → NoC/D2D 争用 → 完成时间与动作量 → 能量/热反馈。主要公式为 M01–M09、M11–M14。

峰值吞吐来自资源数、每周期工作量与频率；持续吞吐还受映射利用率、数据供给和同步限制。频率升高会增加需求带宽，也可能触发功耗或热限制。端口/ADC 数变化同时改变面积、能量、并发和布线，不是独立的免费旋钮。

## 场景与优化

单 Die 优先考虑数据复用、bank 冲突、局部容量与流水线。多核考虑共享 SRAM/NoC 和分片。双 Die 比较远端访问、跨 Die 切分及同步；Package 内局部 3D 则增加几何和热约束。HBF 建模为 Flash 能力、控制器和访问路径，放在封装还是板卡由具体拓扑决定。

常用优化是改变数据流、局部存储、切块、外围共享、计算/搬运重叠及精度；目标必须包含端到端延迟和质量。增加阵列规模可能降低 ADC 成本占比，也可能恶化精度、线阻、利用率和热密度。

## 验证与保存

先验证单资源与独立数值参考，再验证共享路径与复合操作。CIM 校验编码可逆性、数值范围、噪声与任务误差；3D 校验层级不混用、垂直链路容量和热模型适用域。保存实例图、参数/成本版本、映射、动作计数、数据版本和精度声明。

## 状态与物理条件补充

CIM 制造差异、编程误差、读噪声与漂移按不同状态尺度管理，见[数值语义](../../docs/methods/workload_and_numeric_semantics.md)。源消费、写入可见和复位按[生命周期规范](../../docs/interfaces/resource_lifecycle.md)处理；变频需保留剩余工作或限制切换边界。端口、垂直连接、热反馈和条件良率见[物理可行性](../../docs/architecture/physical_feasibility.md)。
