# systemmodel：板卡、主机与节点

## 核心与边界

最重要的是计算设备通过什么实际路径获得数据。systemmodel 依赖 contracts、chipmodel、costmodel，组合 Board/Card/Node，维护主机内存、NUMA、PCIe/CXL/DMA/NIC 等节点级资源。芯片内部状态仍由 chipmodel 拥有；系统不复制一套设备状态。

`composition/board` 表达卡和板的组合，`node` 表达主机与设备；`io` 管访问与传输能力，`memory` 管系统地址/内存组织，`topology` 管节点内连接。物理 DRAM/Flash 介质可复用 chipmodel/memory 原语，系统层拥有实例放置与访问语义。

## 交换信息与状态

向 compiler/runtime 输出设备视图、可达路径、地址域、NUMA 距离、访问能力和共享约束。接收搬运与访存请求，输出接受、背压、完成和注入统计。NIC、DMA、Root Complex、共享上行链路分别拥有队列或资源占用；跨节点 fabric 只引用 NIC 端口。

| 参数族 | 主要字段 | 影响链 |
| --- | --- | --- |
| 主机与 NUMA | CPU/内存归属、容量、带宽、远端代价 | 页放置 → 路径 → 可用带宽/延迟 |
| PCIe/CXL | lanes、速率、协议效率、共享层级、语义能力 | 设备流量汇聚 → 上行争用 |
| DMA | 引擎数、队列、传输粒度、启动成本 | 小块开销、并发数与重叠 |
| NIC | 注入/接收带宽、端口、队列、传输能力 | 本地内存路径与集群带宽共同限制 |
| 内存扩展/卸载 | tier 容量、访问粒度、缓存和预取策略 | 命中率/搬运量 → 设备等待 |

CXL 的连接不自动代表所有设备具有统一一致性；GPUDirect/RDMA 等能力必须显式声明。软件 launch/提交成本归 runtime，硬件 DMA/NIC 服务归本模块，避免两次收费。

## 逻辑链与数学方法

每次搬运定位源/目标 → 判断访问能力 → 选择直接访问或 staged copy → 分解内存、DMA、总线阶段 → 竞争资源 → 完成可见。CPU 内存 → staging → GPU 与直接路径具有不同容量、流量和启动开销。

链路有效带宽用 M04，排队用 M07，共享路径下界用 M06，活跃内存用 M09。单卡峰值之和不等于节点可供给带宽；多条设备支路经过同一个 Root Complex 时需共同计入上行容量。

## 情况与优化

单卡关注主机开销与设备饥饿；同机多卡关注 P2P 可达性、共享 PCIe 及内存压力；异构节点关注 layout/dtype 转换、迁移和串行阶段；HBF 卸载关注页访问、预取深度与 staging 容量。

优化优先顺序是减少不必要的跨域数据移动、改善放置和批处理、重叠搬运，再增加带宽或引擎。预取太早会增加活跃内存和写放大，太晚无法隐藏延迟。

## 验证与留存

验证直接/间接路径、权限、一致性范围、两个设备争同一上行、NUMA 远端访问及 NIC 注入限制。保存路径选择、设备视图、地址域、每段流量与队列等待，才能解释设备性能没有转化成节点性能的原因。
