# 模块接口与执行约定

## 契约边界

本节定义首版实现应遵守的语义。具体类、函数及序列化 schema 在实现时确定。外部数据格式与编译器内部 IR 分开版本管理；导出器和装载器负责转换与校验。

| 数据对象 | 生成方 | 使用方 | 必备内容 |
| --- | --- | --- | --- |
| HardwareSpec | config 与 chipmodel | compiler、simulator | 版本、资源、能力、连接、约束 |
| WorkloadSpec | workloads | compiler、evaluation | 操作、数据类型、形状、输入和参考规则 |
| ExecutionPlan | compiler | simulator | 资源映射、缓冲分配、操作、依赖 |
| SimulationResult | simulator | evaluation、tests | 运行状态、输出引用、指标、配置标识 |
| TraceEvent | simulator/trace | evaluation、调试工具 | 时间、操作、资源、事件、阻塞原因 |

## 硬件与负载描述

HardwareSpec 为每个计算、存储、传输和控制资源分配唯一标识，声明支持的操作及资源连接。动态行为的选择也属于配置，例如仲裁策略、路由规则和队列深度。

容量与地址以字节表示，带宽以字节每周期或字节每秒表示并显式标注。单时钟模型声明时钟频率和周期单位；引入多时钟域时声明时钟域、转换规则及统一时间单位。

WorkloadSpec 声明操作语义、输入输出的数据类型、形状及布局。数值规则包括累加精度、舍入、溢出或饱和处理，以及结果比对容差。参考实现独立于目标硬件模型。

## 执行计划

ExecutionPlan 包含计划版本、目标硬件配置哈希、负载标识、缓冲区表和操作表。计划导出时固化这些信息；每次运行另外记录输入数据哈希。

| 对象 | 必备字段 | 校验要求 |
| --- | --- | --- |
| 缓冲区 | 标识、存储资源、偏移、字节数、布局、生命周期 | 地址有效，容量满足，活跃区间内重叠有依据 |
| 操作 | 标识、类型、目标资源、输入输出、属性、依赖 | 标识唯一，类型受支持，资源及数据引用存在 |
| 搬运操作 | 源区域、目标区域、字节数、传输路径 | 区域不越界，路径连通，完成时目标数据可见 |
| 计算操作 | 操作码、形状、精度和缓冲区引用 | 数值语义明确，资源能力满足 |
| 同步操作 | 等待的操作或事件、同步范围 | 引用存在，就绪与完成条件明确 |

依赖边表示前驱完成后，后继才具备执行资格；资源可用性仍需在运行时判断。异步操作的完成事件必须对应实际完成，不能仅表示已提交到队列。

首版计划采用有限操作依赖图。循环在导出前展开或转为语义明确的复合操作。装载时检测依赖环、未知操作、越界访问、不支持的精度和配置不匹配，并给出对象标识与原因。

存在数据复用或地址别名时，计划必须记录合法生命周期和访问顺序。读后写、写后读及写后写冲突应由依赖或已声明的硬件同步规则约束。

## 执行与时间

一次操作依次经历提交、就绪、开始和完成。提交表示进入队列；就绪表示依赖已满足；开始表示取得所需资源；完成表示规定的效果已可观察。轨迹可按需要记录各状态。

同一时刻的事件按照固定阶段和稳定标识处理，例如先释放完成资源，再更新依赖并仲裁新请求。阶段顺序属于仿真语义，必须记录，避免结果依赖容器遍历顺序。

延迟、发射间隔和占用时间分别建模。流水线延迟为多个周期时仍可能每周期接受新操作；只有模型明确采用非流水执行时，才能将整个延迟视为独占时间。

传输拆分为链路、存储端口等阶段时，各阶段的时间与资源占用只计入一次。多个阶段能否重叠由模型声明。预计时间和实际时间采用不同字段保存。

所有操作完成且输出写回后，运行正常结束。存在未完成操作但无可推进事件时，运行以死锁或无进展错误结束。超时或最大事件数限制由仿真配置单独声明。

## 输出与版本

SimulationResult 记录运行状态、错误信息、输出位置、仿真时间、资源计数器、模型精度和版本标识。错误运行保留诊断记录，汇总性能时单独列出失败数量。

TraceEvent 至少包含时间及单位、操作标识、资源标识和事件类型。记录等待时说明依赖、端口、队列或带宽等原因。大规模轨迹可以关闭或采样，统计计数器独立维护。

每类外部对象携带 schema_version。装载器明确列出支持版本；不支持的版本直接报错。新增可选字段和改变原有字段语义分别处理，并为需要兼容的历史格式提供显式转换。
