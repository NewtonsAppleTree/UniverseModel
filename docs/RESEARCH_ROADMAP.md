**候选收录与接入优先级分开。** 每个进入正式选型的模块至少横向核对三个相关候选，比较 GitHub stars/维护状态、论文影响、功能与精度、接口、独立验证、构建/依赖及许可。主流高热度项目必须进入比较；不因暂时不接入而从总表移除。依赖组件和不同抽象层先分清角色，实际性能比较只在一致条件下进行。

### 每次调研要形成决策

每个候选记录问题与抽象层级、输入输出、状态和资源归属、模型假设、支持范围、校准方法、构建条件、固定版本、许可、运行成本、复现结果，以及在本项目中的角色。阅读实现时重点追踪一条工作路径和一项结果的来源，不要求先读完整仓库。

对选定问题补做最近三年的论文检索和前向引用追踪，覆盖相关 ISCA/HPCA/MICRO/ASPLOS、MLSys、AI 与 EDA 工作。首轮高引用清单提供基础方法；较新的低引用研究也可能已经解决拟议问题。

调研结束后在 [decisions](decisions/README.md)新增选型记录，回答：为什么使用这个基线、为什么需要 UniverseModel 扩展、什么证据会否定当前假设。研究新颖性尚未建立时，继续称为平台验证实验。

## 3 推荐的首个实验

**首批进展：** 本节范围中的独立线性任务、两策略计划、容量/流量、功能解释、参考、分析下界和记录回读已实现，见[指南](../evaluation/docs/linear_mapping.md)。当前仅为小规模标准库实验，未接入外部工具、代表性 AI profile、条件成本或事件执行；后续验收不能据此全部标为完成。

### 问题与边界

建议以 **AI 线性算子的分块、数据驻留与资源瓶颈**作为首个接口验证问题：给定明确的算力、片上容量和外存带宽，MatVec/GEMM 的形状与映射怎样改变数据移动、合法性和性能边界？增加计算资源、buffer 或带宽分别在哪些条件下有效？

这一问题能够复用当前 GEMM/MAC、SRAM、搬运与静态资源模型，同时连接 Timeloop/ZigZag 等外部工具。它先用于检验平台和建立基线；通用性、既有 roofline 规律或复现结果本身不自动构成论文创新。

### 最小范围

| 维度 | 首版要求 |
| --- | --- |
| 任务 | 显式 `M/N/K`、轴语义、dtype、累加精度、输入身份、输出语义；从小型 MatVec/GEMM 开始 |
| 功能参考 | 小整数案例用独立精确参考；引入浮点后规定容差并使用独立参考实现；不能只验证工作量公式 |
| 负载覆盖 | 可手算小例子、矩形、非整除分块、容量边界；再加入来源明确的 AI 层形状，覆盖小 M 与大 M |
| 方案 | 至少两种显式合法映射，例如不同驻留/分块方案；先支持手工计划，再实现有限枚举 |
| 资源预算 | 固定计算资源、buffer、精度、频率和带宽；硬件预算变化单独列为实验组；缺面积模型时不能宣称等面积比较 |
| 计划检查 | 数据依赖、ROI 覆盖、partial 归并、资源引用、buffer 活跃量及容量约束；非法方案保留原因 |
| 账本 | MAC/物理动作、各层读写字节、输出与部分和搬运、显式初始化/装载范围；明确计算/传输重叠假设 |
| 时间 | 分析下界和估计分开；平台宿主运行时间单独记录；没有事件执行证据时不报告仿真实测时延 |
| 成本 | 通过带条件/来源的 profile 查询已覆盖动作；未知项保持未知；局部能量不能命名为整芯片能耗 |
| 产物 | 输入/参数/计划/版本/成本来源/假设、验证结果、失败记录和比较表；能从已保存记录重建表格 |

小 M / 大 M 的线性算子可代表某些 decode / prefill 计算形状，但完整推理还包含 attention、KV、其他算子、通信和调度。首版报告限定在算子或声明的 ROI。现有 CIM array + DAC/ADC + buffer 台架在同一任务语义下逐步接入，先完成[精确 MatVec 与局部验收](architecture/composable_simulation.md)；71-cycle 仍是特定假设下的待验收方案。

### 首次验收的四道门槛

1. **语义成立。** 输出与独立参考一致；输入 shape、精度和边界案例得到覆盖，错误计划明确被拒绝。
2. **计量成立。** 小例子的动作、字节、容量与手算一致；摘要模型和外部细模型各自拥有明确计量范围，避免重复收费。
3. **比较成立。** 同一工作负载与声明预算下比较方案；解释和外部工具的差异，包括布局、累加精度、映射限制与重叠规则。不同模型相互吻合只构成交叉检查。
4. **证据可重放。** 固定源码、工具/依赖和输入；保留合法/非法/失败点；从产物重建结论，准确标记功能、分析、仿真、实测与未知。

通过这四项后，才能用该闭环扩展问题。只有真实测量或独立物理/实现证据覆盖到的范围，才能声称相应的性能或成本有效性。

### 训练方向的后续最小实验

2026-11-23 进展：已完成[训练首批](development/training_step_plan.md)，包含 1–16 层无 bias 的 float64 Linear/ReLU/identity、mean MSE、全部梯度、plain SGD、双容量/生命周期、有限方案和保存回读。PyTorch 2.5.1 CPU autograd/SGD 已做功能对照；完整框架/分布式、物理性能和成本校准仍未完成。此记录更新已有训练路径的能力，不改变第 1 节当前逐模块开发安排。

训练与推理都属于核心研究范围。首个 GEMM/MatVec 实验建立共享的语义、映射和计量基础；软件调研同时准备一个小型 MLP/Transformer block 的 forward/backward/optimizer step 规约。先在 CPU 校验输出、梯度、参数更新及状态账本，再在具备合适设备时，从 PyTorch/FSDP、Megatron、DeepSpeed、TorchTitan 选择语义可对齐的子集比较两种策略。

训练实验固定模型/数据/精度/优化器、全局与微 batch、累积步数、质量标准、拓扑及重计算/offload 策略。报告峰值显存、计算和通信、step time、吞吐、checkpoint 成本；改变 batch 或数值方法时检查收敛及达到质量目标的时间。单作业并行与多作业集群调度分别建模；没有多 GPU 条件时只完成所能验证的数值/分析部分。

### 既有线性路径的十日建议

以下为2026-11-20的线性路径安排，保留作为研究工作拆分；当前模块顺序以第1节和chipmodel开发计划为准。

- **第 1–2 日：** 基于已有线性实验明确外部对照范围，清点 GPU/显存/互连/操作系统；精读 Timeloop/Accelergy 和后继工具接口，选定运行版本。
- **第 3–5 日：** 完成 Timeloop、ZigZag、SCALE-Sim、MAESTRO、AccelForge 的横向调查卡，再运行匹配的小 GEMM 案例，记录映射和动作成本并解释差异。
- **第 6–7 日：** 追踪选定问题的相关工作与新颖性；阅读 LLMCompass 的建模和 AE 路径，选择与当前范围匹配的子实验。
- **第 8–10 日：** 完成选型记录与对照规约，将训练 Linear 前向/反向/更新、短链与成本查询拆为独立任务；先验收一个训练 step 的梯度/更新/工作量，再扩展框架适配。需要 GPU 的性能项在资源具备后执行，CPU 上仍可完成数值与账本检查。

E/F 的资料初筛穿插在上述接口核对中，交付编译/部署边界表及训练规约即可；不将十日计划扩大成全部框架构建。需要额外环境、设备或深度复现的候选另行估时。

## 6 校准和论文证据怎么组织

### 有设备与无设备的两条路径

| 条件 | 可以推进的工作 | 结论范围 |
| --- | --- | --- |
| 本地 CPU / 尚无确定 GPU | 独立功能参考、静态映射、容量/流量账本、分析工具与公开 artifact 复现 | 分析或外部仿真结果；公开 profile 只适用于其原设备/版本条件 |
| 一张合适 GPU | PyTorch/Triton 的受控 kernel 测量、显存/带宽相关校准、小模型或层级实测 | 限定设备/软件栈/shape/dtype；不能据此验证假想 CIM 的物理能耗 |
| 多 GPU / 单节点 | NCCL microbenchmark、TP/PP 或内存分片/通信重叠 | 限定本节点拓扑；容量收益、通信与计算收益分别记录 |
| 多节点 / 集群 | ASTRA-sim/SimAI 校准、网络与大规模扩展实验 | 同时说明网络配置、路由/拥塞、计算 profile 与抽样范围 |
| RTL / 工艺库 / EDA 条件 | 局部 Verilator/Yosys/OpenROAD 验证，补充相应 PPA | 以工艺库、约束和实现层级为条件；当前不以流片为交付 |

### 每个正式课题的实验包

需要具备：有条件的研究命题、相关工作差异、强基线与调优预算、独立正确性/AI 质量验证、完整成本范围、校准与留出集、消融/敏感性、多个负载和无收益案例、可重现脚本与原始记录。协议按[实验有效性](methods/experiment_validity.md)执行。

不要为所有模型预先指定统一“误差小于某百分比”门槛。先确定要区分的效果量和必要精度，再冻结验收标准。例如候选收益与测量噪声/模型误差相当时，需要更多独立数据、更细模型或降低结论强度；两个共享同一成本后端的工具吻合，并不构成独立物理校准。

优化搜索同时记录宿主计算开销、评估预算、非法点、超时与失败。目标硬件时间和平台搜索运行时间分别报告；EDA/自动化方法的贡献也应评价搜索效率、约束满足与生成方案验证。

## 7 后续研究方向如何选择

| 方向 | 可能研究的机制 | 首要证据 | 模块扩展触发点 |
| --- | --- | --- | --- |
| AI 加速器 / CIM 协同设计 | 数据驻留、层间映射、数值精度与外围资源协同 | 功能/质量、完整动作与成本、架构或实现校准 | 现有单元无法表达新机制时细化 chipmodel/costmodel/compiler |
| LLM 推理系统 | KV 管理、调度、异构阶段放置、容量与延迟权衡 | 实机强基线、到达/长度分布、TTFT/TPOT/goodput 与服务失败 | 加入 runtime、系统路径和事件模型 |
| 分布式训练 | 内存分片、计算/通信重叠、拓扑感知策略 | time-to-quality、显存、collective 与扩展性 | 加入节点/集群及通信仿真 adapter |
| AI/EDA 设计自动化 | 约束感知搜索、映射优化、成本代理模型 | 同预算搜索、留出设计/负载、候选实现验证 | 扩展 evaluation 和外部 EDA/成本接口 |

这些都是候选方向，尚未宣称创新成立。R1 后选择一个主问题；其余方向作为可替换场景检验接口，长期使命保持稳定。
