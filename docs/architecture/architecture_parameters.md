# 芯片架构结构参数与设计方法

UniverseModel 的架构设计从工作负载和约束出发，联合决定计算单元、存储层次、互连、控制和软件映射，再用功能与性能模型验证。本文整理结构与参数的中英文术语、参数获取方法，以及从 CIM 宏单元构建异构系统的步骤。当前阶段采用软件模型；关键成本参数可在后续用电路、RTL 或实测结果校准。

## 1 架构层次与概念边界

架构规格要说明支持哪些操作、采用什么数值语义、有哪些资源，以及软件怎样使用这些资源。微架构进一步规定流水线、队列、端口、仲裁和数据通路。芯片物理实现决定这些选择在工艺、布线、供电和散热约束下能否达到目标。

### 1.1 CIM 与异构的关系

**CIM 和异构属于不同的设计维度。** CIM 说明计算与存储怎样结合；异构说明多种计算资源怎样协作。一个系统可以同时采用 SRAM CIM、数字矩阵单元、向量单元和控制 CPU，也可以完全由数字单元组成。

| 维度 | 英文术语 | 要回答的问题 |
| --- | --- | --- |
| 计算位置 | Compute In Memory / In-Memory Computing，CIM / IMC | 计算在存储阵列内、外围还是远离存储的位置发生 |
| 计算域 | Digital / Analog / Mixed-Signal | 运算依靠数字逻辑、模拟物理量，还是两者结合 |
| 存储介质 | SRAM / RRAM / PCM | 单元如何保存数据，是否易失，读写有什么限制 |
| 系统组织 | Heterogeneous Computing | 不同类型的处理单元怎样分工和共享数据 |
| 物理集成 | Monolithic Die / Chiplet | 功能放在一片裸片还是多个互连的裸片上 |

SRAM 是 Static Random-Access Memory；RRAM 或 ReRAM 是 Resistive Random-Access Memory；PCM 是 Phase-Change Memory。SRAM CIM 也可以采用模拟计算，不能把 SRAM 等同于数字 CIM，把非易失存储等同于模拟 CIM。

PIM（Processing In Memory）在不同文献中有宽窄不同的用法。项目建议用 CIM 表示计算直接利用存储阵列或其紧耦合外围，用 Near-Memory Computing 表示独立逻辑靠近存储；引用文献时保留作者的定义和实际数据路径。

### 1.2 从系统到单元

常用层次是 System / SoC → Die / Chiplet → Tile / Core → Macro → Subarray → Cell。Tile、Core 和 Macro 在不同论文中的边界不同，工程中必须按资源和端口重新定义。

| 层次 | 建议在 UniverseModel 中表达的边界 | 主要连接 |
| --- | --- | --- |
| System / SoC 系统 | 主机、加速器、外部存储及系统接口 | 命令、外存请求、完成通知 |
| Die / Chiplet 裸片 | 时钟、电源、封装和跨片通信边界 | Die-to-Die 链路 |
| Tile / Core 计算簇 | 可独立派发任务的一组计算、缓冲和控制资源 | 片上网络与共享存储 |
| CIM Macro 宏单元 | 阵列及执行一次完整宏操作所需的外围 | 输入、权重装载、结果、完成事件 |
| Subarray 子阵列 | 共享局部字线、位线或外围的阵列分区 | 局部选择、感测和累加路径 |
| Cell 存储单元 | 存储状态与读写、计算相关物理行为 | 阵列内部电气连接 |

不要仅凭名称嵌套模型。若某论文的 Core 已含 ADC、局部 SRAM 和路由器，应按实际内容拆分或封装，避免面积、延迟和能耗重复计算。

## 2 通用结构和参数

下列参数构成架构建模的检查范围。具体项目按目标负载选取；没有缓存、虚拟通道或模拟转换器的结构不应保留无效参数。

### 2.1 工作负载与数值语义

| 对象与英文术语 | 需要记录的参数 | 对设计的影响 |
| --- | --- | --- |
| 算子 Operator | 类型、输入输出形状 Tensor Shape、依赖、动态形状范围 | 决定计算能力和控制复杂度 |
| 任务规模 | Batch Size、Sequence Length、并发数、到达间隔 | 决定吞吐、延迟和存储需求 |
| 精度 Precision | 输入、权重、累加和输出位宽；整数或浮点格式 | 影响阵列映射、带宽和数值结果 |
| 量化 Quantization | Scale、Zero Point、舍入 Rounding、饱和 Saturation | 影响跨单元结果一致性 |
| 稀疏性 Sparsity | 比例、块形状、索引格式、动态变化 | 只有硬件与映射支持跳过时才减少执行成本 |
| 数据复用 Data Reuse | 权重、输入和部分和复用次数；Working Set | 决定数据驻留位置和片上容量 |
| 运算强度 Arithmetic Intensity | 指定存储边界上的有效运算数 / 搬运字节数 | 判断计算或数据搬运是否限制性能 |
| 验收指标 | 端到端延迟、吞吐、能耗、面积、任务精度或误差 | 定义可接受的设计空间 |

训练和推理应分别建模；训练涉及梯度、中间激活、优化器状态及更新。如果目标包含大模型，Prefill 与 Decode 也应分别统计，因为并行度、权重复用和 KV Cache 访问不同。

### 2.2 计算资源

| 对象与英文术语 | 需要记录的参数 | 对设计的影响 |
| --- | --- | --- |
| PE 处理单元 Processing Element | 数量、支持操作、每次发射的运算数 | 决定理想并行计算能力 |
| MAC 乘加 Multiply-Accumulate | 输入和累加精度、每周期数量、饱和规则 | 决定数值语义及峰值吞吐 |
| SIMD 单指令多数据 | Single Instruction Multiple Data；Lane 数、向量长度、掩码、数据类型 | 决定逐元素和向量运算效率 |
| Systolic Array 脉动阵列 | 行列数、注入方向、数据流、填充和排空延迟 | 决定形状适配和有效利用率 |
| Pipeline 流水线 | Latency、Initiation Interval、Occupancy | 分别决定完成延迟、连续发射能力和资源占用 |
| SFU 特殊函数单元 | Special Function Unit；除法、指数等操作及精度 | 支持归一化、非线性等运算 |
| Reduction 归约单元 | 归约宽度、树结构、累加位宽、吞吐 | 合并部分和并支持统计操作 |
| CPU 可编程核 | ISA、核数、发射宽度、分支预测；乱序实现另设 ROB 和发射队列 | 影响通用程序和控制执行能力 |
| GPU 执行组织 | SIMT、Warp 大小、常驻线程、寄存器及共享存储 | 影响延迟隐藏、分支分歧和并发度 |

ISA 是 Instruction Set Architecture；ROB 是 Reorder Buffer；SIMT 是 Single Instruction Multiple Threads。CPU/GPU 的内部细节按模型目标逐步引入，作为控制核使用时可以先抽象其命令服务能力。

利用率 Utilization 是负载、映射和资源争用的结果，不能把固定的“80% 利用率”同时当作所有设计的硬件属性。稀疏等效 TOPS 与实际执行运算数必须分别统计。

### 2.3 存储层次

| 对象与英文术语 | 需要记录的参数 | 对设计的影响 |
| --- | --- | --- |
| RF 寄存器文件 Register File | 深度、字宽、读写端口数、访问延迟 | 支撑最近端的数据复用 |
| SRAM / SPM 片上存储 | 容量、Bank 数、每 Bank 深度与宽度、端口类型 | 决定可驻留的数据量及并行访问能力 |
| Cache 缓存 | 容量、Line Size、Associativity、替换和写策略 | 决定命中、缺失和额外流量 |
| Bank 存储分体 | 地址交织 Interleaving、独立端口、冲突规则 | 决定并发请求能否同时完成 |
| Buffer 缓冲区 | 深度、双缓冲、生产消费规则、生命周期 | 决定计算与搬运能否重叠 |
| ECC 错误纠正码 | 校验位、编码延迟、有效容量 | 改变物理容量和可用容量的关系 |
| DDR / LPDDR / HBM | 容量、通道、数据率、总线宽度、访问时序 | 约束片外数据供应 |
| Memory Controller | 请求队列、调度、读写切换、刷新、地址映射 | 决定持续带宽与排队延迟 |

SPM 是 Scratchpad Memory，由软件显式管理。它与硬件管理的 Cache 应分别表达。DDR 是 Double Data Rate；LPDDR 是 Low-Power DDR；HBM 是 High Bandwidth Memory。DRAM 行命中 Row Hit、行冲突 Row Conflict、突发 Burst 及 Bank 并行性影响持续带宽，不能只用标称 GB/s 代替访问模型。

如果系统支持虚拟内存，还需建模地址翻译：MMU（Memory Management Unit）、TLB（Translation Lookaside Buffer）的项数与页大小、缺失延迟和 DMA 地址空间。仅采用物理地址的首版模型应明确该限制。

### 2.4 数据传输与控制

| 对象与英文术语 | 需要记录的参数 | 对设计的影响 |
| --- | --- | --- |
| DMA 直接存储器访问 | 通道数、突发长度、启动开销、未完成请求数 | 决定搬运并发度和小传输成本 |
| NoC 片上网络 Network-on-Chip | Topology、Routing、链路宽度和速率 | 决定通信路径和共享瓶颈 |
| Router 路由器 | 端口数、流水级、缓冲深度、仲裁 Arbitration | 决定冲突、排队和单跳延迟 |
| Flit / VC | 流控单元位宽、Virtual Channel 数、信用 Credit | 决定网络流控与阻塞行为 |
| 广播与归约 | Broadcast、Multicast、Reduction 的硬件支持 | 决定权重共享和部分和合并成本 |
| Command Queue 命令队列 | 深度、发射宽度、顺序规则、完成条件 | 决定任务派发开销和并发能力 |
| 同步 Synchronization | Event、Barrier、依赖与数据可见性 | 保证执行顺序和结果正确 |
| 一致性语义 | Cache Coherence、Memory Consistency | 规定共享数据如何被各处理单元观察 |
| 时钟与电源域 | Clock / Power Domain、频率、电压、CDC 开销 | 决定统一时间换算和跨域通信 |

DMA 是 Direct Memory Access；CDC 是 Clock Domain Crossing。Coherence 描述同一地址多个缓存副本的协调；Consistency 描述访存顺序的可见规则。首版加速器可以采用显式 DMA 和同步，但必须明确完成事件何时保证数据可见。Backpressure（背压）表示下游容量不足时限制上游继续发送。

### 2.5 物理实现与成本

PPA 是 Power、Performance、Area。需要记录目标工艺、目标频率、电压、面积和功耗预算；成本模型还要声明 PVT（Process、Voltage、Temperature）条件、动态能量 Dynamic Energy、漏电功率 Leakage Power 和占用面积。

目标频率是设计约束，布局布线后满足时序的频率是实现结果。时钟树、供电、布线、测试逻辑、冗余和封装都会产生开销。架构模型只覆盖部分开销时，应在面积与能耗报告中明确统计边界。

## 3 CIM 必须额外表达的参数

### 3.1 阵列与数值表示

| 对象与英文术语 | 需要记录的参数 | 必须区分的语义 |
| --- | --- | --- |
| Array 阵列 | Rows、Columns、子阵列数、可并行激活的行数 | 总行数不等于一次能参与计算的行数 |
| Cell 单元 | 介质、每单元位数 Cell Bits、可用状态范围 | 单元位数不等于权重位数 |
| Weight Encoding 权重编码 | Weight Bits、Signed Encoding、Differential Pair | 负数表示及冗余会占用额外单元 |
| Bit Slicing 位切片 | 切片数量、放置位置、合并方式 | 高位宽权重可能占多个列或宏 |
| Bit Serial 位串行 | 每次处理的输入位数、相位和时序 | 输入位宽可能改变一次逻辑运算的周期数 |
| Partial Sum 部分和 | 累加位宽、跨行块和跨宏归约、输出量化 | 宏内结果不一定是完整算子结果 |
| Weight Residency 权重驻留 | 装载容量、换入策略、重用次数 | 决定装载成本能否摊销 |

### 3.2 外围与非理想性

| 对象与英文术语 | 需要记录的参数 | 对结果的影响 |
| --- | --- | --- |
| ADC 模数转换器 | 分辨率、数量、共享比例、转换延迟与能量 | 约束输出精度、吞吐和外围成本 |
| DAC 数模转换器 | 分辨率、数量、输入编码和驱动能力 | 决定输入表示；部分设计采用脉冲或位串行驱动 |
| Sense Amplifier 感测放大器 | 感测方案、延迟、能量 | 影响读出或计算判决成本 |
| MUX 多路选择器 | 共享结构、选择数量和切换开销 | 外围共享通常减少面积并增加服务时间 |
| Shift-and-Add 移位累加 | 数量、位宽、流水线、累加顺序 | 合并切片和分批计算结果 |
| Program / Write 编程写入 | 写入与校验延迟、能量、并发限制 | 尤其影响频繁更新权重的方案 |
| Variation / Noise 变异噪声 | 器件差异、读取噪声、分布与随机种子 | 改变数值误差及任务精度 |
| IR Drop / Drift | 阵列压降、电导漂移、时间和温度依赖 | 约束阵列规模和校准频率 |
| Endurance / Retention | 写入寿命、保持时间、刷新或重编程机制 | 依器件决定长期运行和更新限制 |
| Calibration 校准 | 校准表、频率、面积、时间和能耗 | 修正误差，同时产生系统成本 |

ADC 是 Analog-to-Digital Converter；DAC 是 Digital-to-Analog Converter；MUX 是 Multiplexer。纯数字 CIM 通常不需要模拟乘加路径的 ADC/DAC。噪声、漂移和寿命参数按器件与电路选择启用。ADC 标称位数、有效位数 ENOB（Effective Number of Bits）和任务最终精度不是同一指标；应把硬件误差带回工作负载验证。

### 3.3 一个容量与并行度例子

假设一个阵列有 256 行、256 列，每单元存 2 bit，使用 8 bit 无符号权重；每个逻辑权重占同一行的 4 列。假设所有单元均可用于权重，暂不计差分编码、冗余和校验。

- 物理存储量为 256 × 256 × 2 / 8 = 16 KiB。
- 可存 16,384 个 8 bit 权重，对应一个 256 输入、64 输出的逻辑矩阵。
- 如果每次最多激活 128 行，完整点积至少需要两个行分组结果再合并。
- 如果 8 bit 输入采用逐位串行处理，同一阵列的一次逻辑矩阵向量运算至少涉及 2 × 8 = 16 个阵列求值相位。

这些相位不直接等于时钟周期数。ADC 共享、切片读出、流水重叠、移位累加和跨宏归约共同决定延迟与发射间隔。不能由 256 × 256 的阵列尺寸直接得到“每周期 65,536 次完整 8 bit MAC”。

## 4 参数分类与获取方法

### 4.1 分开管理四类数据

| 类别 | 例子 | 获取与更新方式 |
| --- | --- | --- |
| 设计变量 Design Knob | 宏数量、阵列行列、Bank 数、队列深度、目标频率 | 由约束和搜索空间指定；改变后检查依赖 |
| 特征化数据 Characterization | SRAM 读能量、ADC 延迟、宏面积、最高可用频率 | 工具估算、电路仿真、IP 数据或实测 |
| 派生量 Derived Quantity | 总容量、理想带宽、逻辑权重容量、峰值算力 | 从设计变量和成本模型计算；界面只读 |
| 运行结果 Run Metric | 端到端延迟、持续带宽、利用率、任务精度、总能量 | 在特定负载、输入和映射下仿真或测量 |

同一个字段可能出现在不同角色中，例如目标带宽与实际持续带宽，名称必须区分。改变阵列规模、ADC 分辨率或频率时，原有能耗和延迟数据可能失效；系统应重新查询成本模型或标记缺少有效数据。

### 4.2 参数来自哪里

| 来源 | 适合获得的参数 | 使用条件 |
| --- | --- | --- |
| 工作负载分析 Profiling | 形状、访存量、依赖、动态精度和稀疏度 | 覆盖代表性输入与阶段 |
| 产品或 IP 规格 | 接口、时序、容量、峰值带宽、支持精度 | 核实版本、工作模式和统计边界 |
| Memory Compiler | SRAM 宏容量、端口、面积、时序、功耗表 | 绑定具体工艺和合法宏组织 |
| Liberty 等特征化视图 | 标准单元或宏的时序与功耗条件 | 核实 PVT、负载和输入转换时间 |
| PDK 与 SPICE | 定制 CIM 电路、ADC、器件及外围成本 | 使用相应工艺模型，覆盖工作条件 |
| RTL 综合与 STA | 逻辑面积、时序、关键路径 | 尚需布线及活动信息完善成本 |
| 布局布线与功耗分析 | 连线、拥塞、时钟树、时序和功耗估计 | 明确寄生参数和切换活动来源 |
| 公开硅片论文 | 实测宏或芯片指标、精度与工作条件 | 对齐工艺、数值精度、稀疏性及是否包含外围 |
| 微基准与硬件实测 | 延迟、持续带宽、争用、功耗和误差 | 控制输入、温度、频率和测量范围 |

没有 PDK 或 RTL 时，可以先使用明确假设和有适用范围的估算，进行敏感性分析。参数未知时保留 unknown 或区间，不能填 0 以让模型运行。把来自不同芯片的最低能耗、最高频率和最小面积拼成一个配置，通常无法代表可实现的设计。

### 4.3 可借鉴的公开工具

| 工具 | 适合解决的问题 | 适用边界 |
| --- | --- | --- |
| Timeloop [2] | 张量算子的体系结构与映射搜索、访存和性能分析 | 依赖负载、映射约束与成本模型 |
| Accelergy / CiMLoop [3] | 组件动作能量、面积、CIM 架构成本 | ERT / ART 依赖插件和特征化数据 |
| CACTI [4] | 缓存和存储组织的时延、能耗、面积估算 | 检查版本和工艺；不能直接代表先进节点实际 SRAM 或 CIM 宏 |
| DNN+NeuroSim [5] | 器件、电路、CIM 层次与任务精度协同评估 | 预测工艺模型不等同于代工厂 PDK 或实测 |
| Ramulator 2 [6] | DRAM 控制器、命令与时序、访问延迟和带宽 | 不替代整片计算与 NoC 模型 |
| ZigZag [7] | 架构与映射联合探索，含数字和模拟 IMC 支持 | 结果取决于支持的架构、映射和成本抽象 |

ERT 是 Energy Reference Table；ART 是 Area Reference Table。各工具承担不同抽象层的工作，不应直接相加可能重复覆盖的能量、面积或延迟。接入 UniverseModel 时先统一操作、单位、统计边界和版本。

### 4.4 每个参数保留的证据

参数定义记录名称、作用域、类型、单位、合法范围、枚举选项、默认规则、依赖及是否可编辑。参数取值另外记录来源类别、引用或文件、版本、工艺电压温度、精度和活动条件、适用范围及不确定性。

例如，某个 SRAM 的 read_energy_pj 必须说明每次动作读取多少 bit、在什么 Bank 和端口组织下、采用哪种电压和活动模型。仅保存一个“2 pJ”无法支持可靠比较；这里的 2 pJ 只是格式示意值。

未知成本先取有依据的上下界，分别运行乐观、标称和保守情形。如果架构排名随成本小幅变化就翻转，应优先校准该参数，而不是直接宣布某个架构更优。

## 5 从 CIM 宏单元构建异构芯片

### 5.1 常见的系统组织方式

当前芯片没有统一结构。通用 CPU/GPU、边缘 NPU、数据中心加速器的可编程性、缓存体系、外存和功耗约束不同。对 AI 加速器，一个可评估的起点是由控制、计算、存储和互连共同组成系统。

主机或控制 CPU 提交命令，DMA 在片外与片上存储之间搬运数据；片上网络连接共享存储和各类 Tile。Tile 内包含计算单元、局部缓冲、累加或归约、发射与完成逻辑。各类单元的数量和组织应由负载分析决定。

NVDLA 展示了卷积计算、缓冲、逐元素、池化及数据搬运等模块的分解 [1]，适合学习资源和控制边界；它不是所有当前 AI 芯片的统一模板。2023 年公开的 64 核 PCM 混合信号 CIM 芯片包含片上通信及数字处理 [8]，说明完整 CIM 系统仍需要数字支持和通信结构。

### 5.2 决定异构分工

| 运算特征 | 候选资源 | 需要比较的成本 |
| --- | --- | --- |
| 稳定、可量化且复用充分的矩阵乘 | CIM 或数字矩阵单元 | 装载摊销、量化误差、阵列利用率、转换与累加 |
| 动态权重或频繁更新的矩阵乘 | 数字矩阵单元，也可评估可快速写入的 CIM | 写入时间、精度、重映射和存储流量 |
| 逐元素、归一化、非线性、归约 | SIMD、SFU、归约单元 | 中间结果大小、数据转换和串行占比 |
| 分支、不规则任务及系统管理 | 控制 CPU 或可编程核 | 派发、同步、主机往返和可编程性 |

CIM 适配性取决于具体电路和工作负载。比如矩阵乘的运算数很大，但权重只用一次、矩阵很窄、要求很高精度或结果搬运很重，系统收益仍可能有限。大模型的固定权重投影与动态 Attention 矩阵也应分别评估。

异构拆分不能只按算子名称。相邻算子融合 Fusion 可减少中间结果写回；拆到不同单元可能多一次搬运、重排、量化和同步。是否拆分要比较整个子图的完成时间、能量和精度。

### 5.3 推荐的设计顺序

1. 定义代表性负载、目标延迟与吞吐、面积功耗预算、允许误差，以及是否包含主机和片外成本。
2. 建立数字基线：计算单元、存储和传输均有完整统计，用于检查映射和成本口径。
3. 建立 CIM 宏模型：明确逻辑操作、权重编码、外围、装载、发射间隔及误差来源。
4. 补齐 Tile：加入输入输出缓冲、局部累加、DMA 或网络接口、派发和同步。
5. 做资源分工与软件映射：决定算子落点、切块、数据驻留、融合和任务顺序。
6. 放大到多 Tile：评估网络与外存争用、负载不均、归约流量和同步开销。
7. 联合探索架构与映射：比较性能、能量、面积和精度约束下的 Pareto 方案。
8. 对决定方案优劣的关键部件做电路或 RTL 校准；面积、封装或带宽问题需要时再引入 Chiplet。

该流程需要迭代。例如发现外存受限，应同时检查片上容量、数据复用和映射，而不只是增加计算宏。改变计算 Tile 数量，也要检查 NoC 和存储端口能否提供新增流量。

### 5.4 必须保持一致的计算口径

**带宽。** 理想带宽 = 每次传输的数据位宽 / 8 × 每秒传输次数 × 独立链路数。持续带宽还受协议、访问模式、仲裁和反压影响，分别标注单向与双向、有效载荷与编码位。

**算力。** 数字计算单元可按 PE 数 × 每 PE 每次发射的 MAC 数 × 频率 / 发射间隔计算理想 MAC/s；各量的精度和粒度必须相同。把一次 MAC 计为 2 ops 时明确声明。CIM 应先计算完整目标精度操作的发射能力。

**延迟。** 端到端延迟由带依赖和资源约束的执行时间线确定。只有完全串行的阶段才能直接相加；计算与传输可重叠时，应由事件与资源模型决定。Roofline 可按 min(峰值算力, 带宽 × 运算强度) 做瓶颈初筛，不能代替完整延迟模型。

**能量。** 总能量可按各类动作次数 × 对应每动作能量，再加各电源状态下漏电功率 × 持续时间汇总。CIM 阵列、ADC、累加、存储、NoC 和片外访问划分互斥统计边界。权重装载需报告冷启动成本，以及实际复用次数下的摊销成本。

**面积。** 组件面积按实际实例累计，共享外围只计一次；另外标明布线、时钟与电源、测试及封装开销是否覆盖。任何 TOPS/W 数字都必须带精度、运算计数规则和系统边界。

## 6 在 UniverseModel 中落地

### 6.1 参数管理与可视化

参数定义应同时驱动文件校验、图形表单和批量扫描。每个字段展示中英文名、单位、合法范围、当前值、继承来源和成本依据。枚举用选择框；有明确连续范围的变量可用滑块；整数、位宽和合法宏组织采用相应约束。

配置按组件默认值 → 基础架构 → 变体覆盖 → 实验覆盖解析，运行时保存不可变快照。可视化界面建议包括资源层次树、连接图、参数编辑、校验问题和方案对比。派生量显示公式与依赖，特征化数据通过成本配置选择；运行结果与可编辑输入分开展示。

改动后逐层检查：字段是否有效，连接与资源是否兼容，成本模型是否仍适用，负载和映射是否可行。涉及位宽、端口、容量和时序的错误应标出具体组件及冲突字段。

### 6.2 模块解耦与数据传递

| 边界 | 交换内容 | 约束 |
| --- | --- | --- |
| 配置到模型 | 解析后的 HardwareSpec、成本配置引用 | 组件只接收所属参数和明确依赖 |
| 模型到编译器 | 操作能力、精度、容量、端口、连接与映射约束 | 编译器不读组件内部队列和动态状态 |
| 编译器到仿真器 | ExecutionPlan：资源、缓冲、操作和依赖 | 绑定硬件快照与负载版本 |
| 组件之间 | 数据请求、接收或背压、完成事件 | 明确操作 ID、端口、缓冲引用、尺寸和时序 |
| 仿真器到评估 | SimulationResult 与 TraceEvent | 包含统计口径、版本、配置及输入哈希 |

大张量使用 Buffer / Tensor Reference 表达：存储资源、偏移、长度、数据类型、形状、布局和量化信息。进程内可以引用共享数据对象；持久化或跨进程时使用文件或块存储引用。数据到达、结果可见和资源释放通过有明确定义的事件表达。

组件模型提供功能和资源行为，仿真器管理时间推进；编译器决定映射与静态依赖，运行时仲裁处理真实冲突。成本模型可替换，但操作语义和统计边界保持一致。详细契约见 docs/interfaces/contracts.md。

### 6.3 首版实现范围

先选择一个代表性矩阵任务及必要的后处理，建立数字基线和一种 CIM 候选。首批配置覆盖精度、矩阵或阵列尺寸、Tile 数、局部存储、片外带宽、DMA、延迟与发射间隔；采用模拟 CIM 时再增加转换、编码和误差配置。

验收时至少说明：功能误差是否达标，计算与传输分别花费多少时间，哪个资源造成等待，能耗主要来自哪些动作；改变一个参数后，性能变化是否能被轨迹解释。完成这个闭环后，再扩展完整计算图、更多异构单元和复杂互连。

参数字典、成本配置和组件注册是后续实现的约定；现有目录骨架及界面原型尚不提供这些后端能力。
