# 工程结构与模块职责

## 建模范围

UniverseModel 支撑芯片架构定义、软件映射、功能验证与性能评估。设计产出包括架构规格、可执行模型、映射计划和实验结果。后续通过关键模块 RTL 的仿真与综合结果校准模型。

`chipmodel` 保存软件实现的架构和微架构模型。计算单元、流水线、缓冲区、端口及仲裁行为均可在该层描述。RTL 后续作为独立实现加入，并对照同一份接口规格验证。

首先确定目标负载、支持的操作、数值精度和资源约束，再选择模型精度与实现语言。当前结构不绑定特定指令集或芯片类型。

## 顶层职责

| 目录 | 负责内容 | 主要产出 |
| --- | --- | --- |
| chipmodel | 硬件资源、内部状态、操作行为与成本估计 | 硬件能力描述和组件模型 |
| compiler | 计算图转换、划分、映射与静态调度 | 可供仿真的执行计划 |
| simulator | 驱动模型执行，推进时间，处理事件 | 输出数据、统计、执行轨迹 |
| workloads | 代表性任务、输入规格与独立参考实现 | 负载定义及正确性基准 |
| evaluation | 实验运行、参数扫描、指标分析 | 可复现的方案对比 |
| tests | 模型、接口与端到端验证 | 自动检查与回归用例 |
| config | 硬件、编译、仿真和实验配置 | 可序列化的运行参数 |
| data | 输入数据与运行结果 | 数据集和实验记录 |
| example | 展示一次完整调用 | 最小可复现示例 |
| docs | 架构规格、接口约定与验证方法 | Markdown 源文档和 Word 汇编 |

`workloads` 描述要执行什么，`config` 描述采用哪些参数，`data` 保存具体数据和结果。大型输入通过清单、校验值和获取方式管理；每次运行保存实际使用的配置快照。

## 芯片模型

各组件分别定义静态参数、运行状态和状态转换。组件可以返回完成事件或延迟估计，统一时间轴由仿真引擎管理。

| 子目录 | 主要参数 | 主要状态与行为 |
| --- | --- | --- |
| compute | 支持操作、精度、并行度、吞吐与延迟 | 发射、执行、流水线占用、完成 |
| memory | 容量、位宽、端口、访问延迟和带宽 | 分配、读写、端口冲突、请求排队 |
| interconnect | 拓扑、链路带宽、路由和传输规则 | 传输、争用、背压、交付 |
| control | 队列容量、发射规则和同步机制 | 就绪判断、派发、仲裁、同步 |

带宽、容量和延迟参数由硬件配置提供，编译器与仿真器读取同一份解析结果。组件之间通过显式端口、请求和事件交互。芯片模型依赖的公共类型应保持稳定，避免依赖编译器内部优化 pass。

## 编译器和仿真器

保留现有编译器目录。下表定义各阶段的职责，具体 pass 顺序由 pipeline 根据数据依赖组织。

| 编译器目录 | 职责 |
| --- | --- |
| ir | 表达计算语义、数据对象及依赖 |
| globalsplit | 全局任务或计算图划分 |
| globalsolver | 全局资源与映射方案求解 |
| tiling | 确定计算块和数据块的粒度 |
| memplan | 分配存储区域并管理数据生命周期 |
| sched | 确定静态顺序、资源映射与依赖 |
| lowering | 转换到目标架构支持的操作层级 |
| interpret | 解释 IR，用于编译语义检查 |
| export | 导出带版本的执行计划 |
| pipeline | 组织 pass，检查输入输出约束 |
| lba | 保留现有目录，职责明确后接入 pipeline |

`simulator/engine` 负责事件队列、时间推进、完成通知和终止判断；`stats` 汇总计数器；`trace` 记录操作和资源事件。组件状态由芯片模型维护。

编译器给出映射及静态依赖。执行时的端口占用、队列阻塞和仲裁由芯片模型表达，仿真引擎推进这些行为。计划中的预计时间用于分析，实际完成时间由仿真得到。

IR 解释器检查编译转换的语义。功能仿真检查执行计划在硬件操作语义下的结果。两者均应与 workloads/reference 中独立实现的参考结果比对。

## 数据流与实现顺序

负载定义与输入数据进入编译器。编译器查询硬件能力，导出执行计划。仿真器装载同一硬件配置和输入数据，执行计划并记录结果。evaluation 完成功能比对、性能分析和方案比较。

硬件配置、执行计划、输入数据通过标识及内容哈希关联。仿真开始前检查引用一致性。参数扫描逐次生成配置快照，是否重新编译由实验目的决定。

| 阶段 | 实现重点 | 完成条件 |
| --- | --- | --- |
| 1 | 最小架构规格和工作负载 | 操作、资源、数据格式及预期输出明确 |
| 2 | 功能模型和最小映射 | 执行输出与独立参考一致 |
| 3 | 时间模型和资源争用 | 延迟与占用符合可手算案例 |
| 4 | 参数扫描和对比分析 | 同一实验可复现，性能变化有证据 |
| 5 | 关键模块 RTL 校准 | 记录模型与 RTL 的差异并更新参数 |

阶段 2 可以采用直接映射，按需要增加编译优化。阶段 3 先建立能够解释瓶颈的时间模型，再细化流水线、队列或逐周期行为。
