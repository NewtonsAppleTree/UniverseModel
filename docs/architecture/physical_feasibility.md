# 物理可行性与长期成本

## 1 结构合法不等于可实现

JSON 引用有效只证明对象连接在语法上成立。实际架构还受端口数量、总线/PHY、I/O 边界、功率供给、热路径、工艺与封装条件约束。首版不需要物理签核工具，但需要标出哪些约束已检查、哪些只是设计假设。

相关行为按所有者落在 chipmodel、systemmodel、clustermodel、costmodel 和 evaluation，不增加一个包办所有细节的顶层模块。每项模型由研究问题触发；未建模项不得被默认成无限能力。

## 2 带宽必须经过真实端点

端到端传输不仅受链路限制，也受源/目标内存端口、DMA、序列化、PHY、控制器、注入接口和协议控制限制。每条路径的能力应与共享资源匹配；两条链路使用同一个 PHY 或上行端口时，不能各自独享该资源峰值。

互连可行性链为：需要的流量/并发 → 端点/通道数量 → lane/bit rate → 有效带宽 → 布局与连接预算 → 功耗及温度。协议效率与有效 payload 带宽的扣除边界只计算一次。

双向链路声明 full-duplex 或 half-duplex；内存读写端口与链路双工独立。增加 D2D 带宽可能要求更多 bump、边缘面积、布线层或更高功耗，不能只修改一个 bandwidth 数值却保持所有成本不变。

## 3 三维结构的几何限制

3D 需要明确垂直端口的位置/密度、有效重叠区域、keep-out、供电与散热路径。所有层连接到同一逻辑 Die 时，共享垂直接口、ADC 或内存控制器可能成为汇聚瓶颈；层数、活跃层数和同时读出能力分别约束。

2.5D interposer、局部桥接与垂直堆叠可组合，技术类型属于连接/stack。封装外部 I/O 与内部 D2D 不应共享一个没有范围的 link_count。早期可用端口和面积预算表示，距离相关延迟/能耗只有在几何有依据时才启用。

用于显示的 UI 坐标与物理位置分开。拖动图标改变布局显示，不应悄悄改变芯片线长、热阻和成本；编辑物理几何必须是显式参数操作。

## 4 功率预算与动态频率

平均能量/时间只能说明平均功率。多个引擎同时活跃的峰值、共享供电域、idle/leakage、power gating 和唤醒延迟都可能影响可用性能。功率状态转换同样需要时间和能量边界。

DVFS 改变的是后续工作完成速率，不应改变已经执行的工作量。若一个动作需要 W 个有效执行周期，跨频率区间应满足 `W = ∫ a(t) f(t) dt`；f(t) 是所在时钟域的频率，a(t) 仅在有效执行时取 1，停顿或等待期间取 0。这只适用于工作可按有效周期累计的模型；若动作受固定物理时间或带宽限制，则不能按频率同比缩放。

为简化，首版可只允许在动作边界切换频率；若支持在途变频，就需保存剩余工作并失效/重排旧完成事件。不能修改 frequency 后继续使用原先固定的 finish_time。

## 5 热和误差的闭环

热模型采用已声明的 RC 或预算层级。若温度驱动泄漏、降频或 CIM 误差，链条为功率积分 → 温度 → 状态/服务率/误差 → 新功率；该链条有状态和时间尺度，不能作为静态配置字段循环求值。

声明控制采样周期、迟滞、温度观测/控制延迟、数值步长与稳定性。过细的热求解会拖慢仿真，过粗则可能漏掉重要反馈；用独立步长敏感性和校准范围判断是否足够。

温度平均值不能代表热点，封装功率预算不能直接推导结温。未建模 PDN、IR drop、电迁移或材料应力时，对应可靠性结论必须保持未覆盖；这些项只在设计选择确实依赖它们时增加。

## 6 良率与成本的条件计算

若研究双 Die/多 Die 的经济性，应分开 wafer cost、dies per wafer、die yield、known-good-die 测试、封装/组装良率和 NRE。制造成本与目标架构延迟是不同目标。

简化 Poisson 良率模型 `Y = exp(-D0 × A)` 要求缺陷独立均匀、D0 与面积单位匹配，不能作为通用实测良率。较小裸片可能提高 die yield，但更多接口、测试和组装步骤也有成本。

若每片输入已是经过筛选且成本包含裸片良率的 KGD，可按声明条件估算 `C_good_package ≈ (Σ C_KGD + C_assembly_attempt + C_test_attempt) / Y_assembly`，这里 Y_assembly 是给定合格裸片的条件组装良率。不能再机械乘一次所有原始 die yield，重复计算同一损失。

上述公式忽略返工、测试漏检、批量议价及混合良率，适合敏感性与结构比较。NRE 可按明确产量摊销，不能从一片芯片面积直接推断总经济优势。

## 7 写入寿命与刷新

HBF/Flash 或非易失 CIM 在频繁更新场景需要 logical write、physical programmed bytes、write amplification、wear leveling、刷新/重映射和可用坏块范围。读为主的静态推理与训练/在线更新是不同情景。

条件寿命可粗略写为 `T_life ≈ usable_programming_budget / average_physical_write_rate`，前提是预算与实际磨损分布可比。总平均写入不能发现热点单元提前耗尽；需要时按最受压区域评估。写放大与刷新成本已含在物理写速率时，不再额外重复乘入。

校准、刷新和故障迁移会占用同一端口/阵列，不应假定后台工作永远免费。保存频率、触发条件和前台阻塞范围。

## 8 故障域与恢复

节点、封装、共享电源、交换机和链路是不同故障域。器件错误、数据错误、请求失败和整机失效分别建模；它们不等价于独立的统一 failure_rate。

只有研究可用性、长作业或可靠性约束时才需要故障注入、冗余和恢复策略。恢复会增加 checkpoint、通信、重算、备用容量与服务中断；多副本共享电源或网络时不能假设独立失效。

执行检查点保存模拟器状态；目标工作负载的 checkpoint 是被模拟的 I/O 和恢复工作，两者分开。关闭故障模型只表示不覆盖故障，不表示证明设备永不出错。

## 9 增加细节的条件

首次性能比较至少检查容量、端口/共享带宽、支持精度和成本工作条件。研究 3D 时增加几何与热预算；研究热限制时增加反馈；研究经济性时增加良率/成本；研究频繁写入和长任务时增加寿命/故障域。

若这些未覆盖项足以改变候选排序，应补数据或缩小结论范围。把所有物理细节一次实现，会掩盖研究优先级；明确哪项未知量能改变决策，才知道下一步该建模或测量什么。
