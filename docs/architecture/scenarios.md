# 分场景架构推演

## 1 共同的推演框架

每种架构都回答七个问题：工作语义是什么；数据在哪；计算资源是什么；必须经过哪些路径；哪些资源共享；参数从何而来；怎样证明收益。物理结构决定可行路径，映射决定需求，运行策略与争用决定完成时间，成本模型给出有条件的代价。

下列场景可组合使用，不是互斥产品类别。CIM 是计算机制也是可独立暴露的资源族；3D 是结构关系；异构是能力与组织差异；集群是系统规模和网络组织。

## 2 单 Die：数字 NPU 与 CIM 对照

结构：共享同一任务、精度与 I/O 边界，候选计算路径分别使用数字 MAC 和 CIM。保持输入/输出存储及 host 边界可比较；面积或功耗预算相同与否要事先声明。

数字路径为 SRAM → MAC/累加 → SRAM；模拟 CIM 路径为权重编码/写入 → 输入编码 → 阵列 → ADC → 数字累加 → 输出。数字 CIM 按真实逻辑保留必要阶段，不默认存在 ADC。

关键参数是有效权重容量、精度、位切片、数组形状、外围共享、数据复用、写入/校准频率和噪声。高复用固定权重可摊薄编程成本；频繁更新或小批量不能假定写入免费。decode 与 prefill 的矩阵形状、并行度和访存比例不同。

判定指标包括端到端延迟、有效吞吐、总能量、面积、任务质量与权重重配置成本。仅报告阵列 MAC 能量会遗漏主要外围和数据移动。使用 M02/M08/M10/M11/M16 检查容量、转换和精度链。

## 3 多核与双裸片 Dual-Die

多核留在 chipmodel。比较任务沿核划分、数据沿核分片或共享缓存三种模式，检查局部工作量、共享 SRAM/NoC 和同步。相同 core_count 在不同核心能力下不可直接比较。

双裸片在 Package 下组合两个 Die；可以平面互连，也可以作为堆叠的一部分。软件可以看到一个 DeviceView 或两个设备，分别影响编译放置、地址域、通信和驱动开销。不要把逻辑设备数当作 compute_die_count。

数据可沿 M/N/K 维分片：输出维分片通常减少输出规约，但可能复制输入/权重；归约维分片引入部分和规约。实际选择依形状、容量和 D2D 而定。

关键参数是 D2D 带宽/延迟/能量、共享或分布式内存、访问粒度、一致性和分片策略。指标包括跨 Die 字节、远端访问比、尾部等待、容量利用率与增量面积/能量。若输出规约成为临界路径，翻倍计算不能带来两倍加速。

## 4 三种 3D CIM 分开建模

| 情况 | 物理结构与数据路径 | 关键参数 | 首要风险 |
| --- | --- | --- | --- |
| 裸片内三维阵列 | 一个 Die 内多层存储/计算阵列 | array_layers、层选择、同时激活层数、读出共享 | 容量与计算并行度被错误等同 |
| 多个 CIM Die 堆叠 | 多 Die 通过垂直链路协作 | die_stack_depth、compute_die_count、垂直带宽、权重放置 | 转换/链路争用与热叠加 |
| CIM + 数字逻辑堆叠 | 存算 Die 与控制/ADC/数字计算 Die 分层 | ADC 位置、层间数据位宽、互连和热边界 | 把外围当免费或遗漏数字累加 |

同一 Package 可以含多个 stack 和平面 D2D；每个 stack 独立声明顺序、几何和连接。HBM stack、CIM stack 的层数不能混为一个全局层数。

比较按容量目标、硅面积预算或封装占地分别控制变量。增加层数可能增加容量、缩短水平距离，也可能增加垂直复用与温升。热 off 只能声明未覆盖，budget 只检查预算，RC 才计算条件温度。

优化选择包含层间映射、ADC 分布、垂直带宽、活跃层调度与热约束下的功率分配。结论需同时给出精度、延迟、能量、硅面积和封装占地，避免只展示密度提升。

## 5 HBF 层级存储与卸载

HBF 在本项目中指 High Bandwidth Flash。先确认具体产品/研究方案的接口、页/块语义、控制器位置、读写性能、并行度与可靠性条件，再选择在 Package 或 Board 中放置。不能从名称推导随机访问时延或自动具有 CIM 能力。

典型路径为 HBF → 控制器/互连 → HBM/DRAM/SRAM staging → 计算，或者在明确支持时采用直接访问。权重、KV cache 或其他对象是否适合卸载取决于访问局部性、复用、写入频率和质量/时延目标。

关键参数是容量、访问粒度、有效持续带宽、请求启动、读写不对称、队列深度、预取窗口和 staging 容量。耐久性与写放大只在涉及频繁写入/长期寿命判断时增加，不把缺失数据填成无限。

先计算每步需要的新数据量，再判断预取能否在前一计算窗口内完成，同时检查峰值缓冲。指标包含 miss/stall、每任务搬运量、介质请求数、写入量和设备等待。容量充足但带宽或访问粒度不适配时，卸载仍可能失败。

## 6 CPU/GPU/NPU/CIM 异构节点

CPU 可执行控制、预处理或不规则操作；GPU 处理通用并行；NPU 处理适配的数据流；CIM 处理合适的驻留权重运算。这些是候选放置，不是固定最佳分工；由负载支持能力、形状与数据代价决定。

路径包含主机内存、设备内存、PCIe/CXL、DMA 和可选 P2P。输入预处理 → 设备计算 → 跨设备转换 → 后处理可能形成串行链。可连通、可 DMA、可一致访问是不同能力。

关键参数是算子支持集、精度、布局、批量、设备内存、传输/launch 开销、NUMA 和共享上行。划分收益必须大于迁移、同步与格式转换代价；使用能力峰值选择最快设备并不足够。

比较整图单设备、阶段分区、算子级动态放置和流水并发。指标包括任务延迟/吞吐、各设备有效利用率、迁移字节、CPU 开销和共享链路占用。加更多设备可能增加等待而非提升吞吐。

## 7 多机多卡与并行策略

物理链为节点内设备 → 本地路径/NIC → fabric → 远端 NIC/设备。rank/group 映射独立于节点数；同一个物理网络可承载多个并行维度。先评估节点供给和注入上限，再评估交换网络。

| 策略 | 英文 | 主要交换 | 重点参数/限制 |
| --- | --- | --- | --- |
| 数据并行 DP | Data Parallelism | 梯度规约或参数同步，依算法而定 | batch、梯度大小、频率与收敛条件 |
| 张量并行 TP | Tensor Parallelism | 激活/部分和的 gather/reduce 等 | 切分维、层结构、频繁启动和带宽 |
| 流水并行 PP | Pipeline Parallelism | 相邻阶段激活及训练反向数据 | stage 平衡、microbatch、bubble 与内存 |
| 专家并行 EP | Expert Parallelism | token dispatch/combine | 路由分布、专家容量、热点与 all-to-all |
| 上下文并行 CP | Context Parallelism | 注意力相关上下文/KV/中间量 | 序列切分与具体注意力算法 |

通信量由算法和实际形状推导；不能仅依据 DP/TP 名称写常数。训练/推理、dense/MoE、prefill/decode 分组分析。使用 M13 作为特定 ring 基线，事件模型验证共享路径与重叠。

优化可先改 rank 放置与分层 collective，再调整融合/分块与计算重叠，最后比较网络升级。强扩展固定总工作量，弱扩展保持每资源工作规模；异构集群另外报告成本/能量和能力差异。

## 8 综合场景的组合顺序

例如多机多卡 3D CIM + HBF 系统：先验证单卡的数值与容量；再验证堆叠外围/热和 HBF 预取；再验证节点内 DMA/NIC；最后引入跨节点划分。每次只增加能够定位误差的新边界。

相应证据依次为参考输出、位映射/转换阶段、局部资源计数、层间流量、节点路径、collective/链路统计与最终指标。一个端到端总时间不能替代这些局部证据。
