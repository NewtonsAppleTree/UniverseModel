# 模型覆盖范围与组合规则

## 1 模型精度应是一组能力

“事件模型”“周期模型”只说明部分时间表达方式。一种 GPU 模型可以有精确数值、粗粒度 kernel 时序、实测总能量和缺失的热行为；另一种 CIM 模型可以有详细阵列时序，却只采用简化噪声。不能用单个 fidelity_level 排出统一准确度。

每个组件模型描述以下维度：操作/数值语义、时序粒度、共享资源与背压、能量边界、面积边界、热行为、错误/故障行为、校准域。每一维分别写 supported、approximate、unmodeled 或不适用，并说明限制；这是未来模型描述契约，不是新增业务模块。

## 2 先判断是否支持再请求成本

能力应表达为关于操作、dtype、累加精度、shape、layout、alignment、稀疏格式和工作条件的谓词，而非一串 opcode。例如“支持 MatMul”不能推导支持任意 K、任意转置和任意低比特打包。

查询链为：语义是否可表达 → 目标是否支持 → 是否可合法 lowering/转换 → 资源/容量是否满足 → 对该条件是否有成本依据。unsupported、infeasible、missing_characterization、out_of_domain 和 internal_error 使用不同结果类型。

静默回退会改变架构比较。若将不支持的算子放回 CPU，必须新增放置、搬运、转换和软件成本，并保存 fallback 记录。合法回退可以是候选策略；零成本回退不是能力实现。

## 3 每个结果项指定唯一计入方

成本归属用覆盖清单而非一个 includes_memory 布尔值。清单至少标出物理范围、动作/阶段、指标类别、时间区间、是否已含静态成本与来源。时间、流量和能量可有不同的权威生产方，但每项必须能核对。

| 组合 | 合法条件 | 不合法的重复 |
| --- | --- | --- |
| 摘要 GPU + 节点 I/O | 摘要边界从设备输入就绪到设备输出可见；外部 I/O 单独计算 | 摘要已含 host copy，却再次加 PCIe/DMA |
| CIM 阵列 + 外围 | 阵列只覆盖阵列动作，ADC/DAC/累加由外围覆盖 | 原始成本已是完整 macro，外围再收费 |
| 存储工具 + 事件模型 | 工具给服务需求/状态代价，组件产生排队等待 | 工具已输出含争用总时延，事件模型再排同一次队 |
| 总能量测量 + 动作计数 | 总能量作为权威结果，动作计数用于解释或独立对照 | 动作动态能量和总能量相加 |
| Cluster + Node + NIC | NIC 属于 Node；fabric 计链路和交换设备 | 按每个 rank 复制整张 NIC 或交换机成本 |

未覆盖项是 unknown/unmodeled；若仍展示已知成本之和，应命名为 partial estimate 并列缺项。unknown 不能当零，禁用功能、真实零成本、参数未知和模型不支持必须区别。

## 4 摘要模型必须保留会影响外部的竞争

若设备摘要只返回固定延迟，就无法自动表达两个任务共享执行槽、memory bandwidth 或内部 buffer。摘要要么声明只支持串行隔离执行，要么提供并发能力、资源服务需求及排队协议，要么使用经过对应并发场景校准的服务模型。

拆分一个实测端到端延迟为“计算+内部访存”并不总是可识别。缺少依据时应保留整体摘要和适用域，不能凭比例分配后声称内部机制准确。若研究结论依赖内部背压，就需要细化模型或限制结论。

混合粒度的接口需对齐数据就绪、可见性、资源释放、计时边界和采样条件。换一个外部工具时至少重跑接口一致性与边界案例，而非只保证函数签名一致。

## 5 数值计算与时间推进可采用不同覆盖范围

小规模功能运行计算真实张量，用于验证语义与误差；大规模性能运行可使用元数据、已验证的工作量和数据位置，只推进服务与资源行为。结果中单独声明功能验证是本次实算、已验证范围内复用，还是未验证。

数据相关分支、稀疏跳过、压缩长度、MoE 路由和提前停止需要真实数据或明确的输入/轨迹模型。改变策略可能改变这些分布；固定旧轨迹只能回答“在该轨迹下”的问题，不能自动预测策略反馈后的系统。

不能把少量数值样本的正确性结论无条件扩展到所有动态 shape、精度和算子。复用证据应绑定范围、模型版本和前置条件。

## 6 配置来源和缓存身份

一组成本条件应作为相互约束的元组保存：technology/process、voltage、frequency、temperature、precision、geometry、provider_version。来自不同条件的最大频率、最低能量和最大容量不能随意组合成同一设备。

静态派生使用无环依赖；温度—泄漏—频率属于动态反馈或显式迭代。UI 修改设计量后显示哪些成本不再适用、哪些能力约束失效。无法校验的物理关系记录为未覆盖约束，不把 schema 通过当作可制造证明。

缓存身份按产物区分：解析配置依赖 schema/覆盖/派生规则；计划依赖语义、能力、编译策略和成本版本；运行依赖实际输入、初始状态、模型及随机方案；分析依赖计数器、测量范围与公式。显示主题不应使性能缓存失效；改变数值规则必须使相关计划和结果失效。

## 7 扩展接口与语言选择

首个闭环可由 Python 统一装配、序列化与分析；热点在性能测量后再考虑 C++/Rust 等实现。公共契约和语义不绑定实现语言。插件声明 ID/version、支持 schema、能力、覆盖范围和依赖；模块通过显式注册装配，不在导入时隐式执行实验或修改全局状态。

参数表达式采用白名单算子或显式派生函数，校验单位和依赖；不需要把任意宿主代码嵌进配置。跨语言接口明确字节序、所有权、错误返回和释放时机，不能用宿主指针代替 DataRef。

## 8 仿真规模本身也受资源约束

记录 host wall time、峰值宿主内存、事件数、trace 大小和每个模拟工作单位的执行成本。它们用于判断工具是否可用，与目标芯片指标分开。

大量重复操作可以表示为循环/复合节点并按需展开事件，避免将整个训练或集群迭代一次展开为巨大 DAG。聚合需保留共享资源需求、可见性边界和可重叠性；若资源竞争或数据相关性会改变下一步，不能直接跳过整个区间。

第一阶段优先精确小例子、可控规模事件模型与抽象设备组合。并行离散事件仿真、回滚和跨进程 checkpoint 是后续工具能力，只有单进程成为明确瓶颈时再实现。

## 9 对应验收

在参数相同、覆盖边界相同的重叠适用域内，对摘要和细模型做差分检查；偏差应有解释和范围。检查 partial estimate 不冒充 total，unknown 不变为零，并发查询不越过适用条件，插件替换不改变数据可见性。

数值正确、结构合法、估计覆盖完整、时序可信和结果可复现是不同证据。接口返回成功，只能证明该接口声明的条件已满足。
