# 验证方法与性能评估

## 模型精度

| 模型层次 | 验证内容 | 结果用途 |
| --- | --- | --- |
| 功能模型 | 计算、访存、同步与数值语义 | 检查输出正确性 |
| 解析模型 | 计算量、数据量和资源上限 | 快速筛选架构参数 |
| 事件模型 | 排队、争用、传输与执行重叠 | 分析延迟和主要瓶颈 |
| 逐周期模型 | 每周期状态变化与控制行为 | 检查关键微架构细节 |

每份结果声明模型层次、覆盖的硬件行为和简化条件。功能模型没有时间精度承诺。面积与能耗估计记录参数来源和适用条件，后续用 RTL、综合或测量结果校准。

## 测试分工

| 位置 | 验证重点 | 代表性检查 |
| --- | --- | --- |
| compiler/tests | IR 与各编译阶段 | 转换前后语义一致、映射满足约束 |
| tests/chipmodel | 组件状态与资源行为 | 容量边界、端口冲突、流水线吞吐 |
| tests/simulator | 事件推进与运行结束 | 并发完成、稳定排序、死锁与复位 |
| tests/contracts | 外部格式和语义约束 | 版本、引用、依赖环、单位及越界 |
| tests/integration | 整条执行链路 | 参考结果比对、统计和实验复现 |

功能测试使用独立参考结果。整数按规定的位宽和溢出规则比较；浮点按负载规定的绝对与相对容差比较，并处理 NaN、无穷和有符号零的约定。

时间模型先通过可手算的小案例：单次计算、单次搬运、两个请求竞争同一资源，以及计算与传输重叠。每个用例列明初始状态、资源约束和预期完成时间。

## 指标口径

| 指标 | 定义 | 必须说明的条件 |
| --- | --- | --- |
| 任务延迟 | 约定终点时间减去起点时间 | 是否包含装载、输入搬运与输出写回 |
| 吞吐量 | 测量区间内完成任务数除以时间 | 预热、测量区间、任务定义 |
| 资源利用率 | 已占用资源时间除以可用资源时间 | 资源粒度、容量和测量区间 |
| 存储峰值 | 同一时刻活跃分配字节数的最大值 | 统计的存储层级与生命周期规则 |
| 数据搬运量 | 指定接口实际通过的字节总数 | 接口边界、方向、重传及重复读取 |
| 等待时间 | 指定操作或资源的阻塞时间 | 阻塞原因及重叠区间处理方式 |

多端口或多执行槽资源使用容量归一化的资源时间。只统计“至少一个槽忙碌”时，指标应命名为忙碌时间比例。多个操作的等待可以重叠，不能将等待时间总和直接当作任务延迟。

仿真程序在主机上的运行耗时单独记录。模型估计的芯片执行时间与主机运行耗时分别展示。

## 实验组织

实验定义放在 config/experiments，执行逻辑放在 evaluation/experiments，分析逻辑放在 evaluation/analysis。每次运行写入独立的 data/runs/<run_id> 目录，并保存以下记录。

| 记录 | 内容 |
| --- | --- |
| manifest.json | 运行标识、代码版本与内容标识、输入哈希、随机种子、环境和运行状态 |
| config.json | 完整解析后的硬件、编译与仿真配置 |
| plan.json | 实际执行的计划；采用其他格式时记录格式与哈希 |
| metrics.json | 指标值、单位、统计区间和模型精度 |
| validation.json | 功能比对结果、容差及失败原因 |
| outputs 和 trace | 输出数据引用；按实验配置保存轨迹 |

尚未提交的代码需要保存补丁及新增源文件快照，或保存可恢复的源码归档。单独记录 Git 提交号不足以复现工作区中的改动。

比较架构方案时固定负载、数值规则和指标口径。硬件参数变化后重新编译，用于比较各配置下的映射结果。研究固定映射的敏感性时，保留映射与静态调度，检查其在新配置下的合法性，再导出绑定新配置哈希的计划。两种实验方式分别标注。

启用随机策略时记录种子并报告重复次数和离散程度。确定性模型使用相同输入重复运行，验证结果一致。汇总结果同时报告有效运行数和失败运行数。

## 首个端到端案例

选择一个代表性任务，明确输入输出、参考结果和数值规则。建立包含计算、存储、传输与控制资源的最小硬件配置，采用直接映射导出执行计划。

验收条件如下。

1. 计划装载通过格式、引用、容量和依赖检查。
2. 仿真输出符合参考结果与规定容差。
3. 至少一个无争用场景的完成时间可手工核算。
4. 至少一个争用场景能从轨迹解释等待原因。
5. 改变一项硬件参数后，记录计划是否变化，并解释性能变化。
6. 保存配置、代码及数据标识后，能够复现输出和指标。

达到这些条件后，再增加负载规模、编译优化和模型细节。RTL 校准从对架构结论影响最大的模块开始，记录校准前后的参数与误差。
