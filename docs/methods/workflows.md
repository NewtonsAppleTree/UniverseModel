# 开发、实验与变更工作流

## 1 设计问题的起点

每次研究先写一个可判断的问题，例如“固定 decode 质量与时延限制，增加 CIM 层数还是增加 HBF 预取更有效”。同时定义工作负载、质量、指标边界、物理/软件约束、基线、可改变量与必须获取的证据。

问题 → 工作需求 → 资源与数据路径 → 参数依据 → 映射 → 执行 → 指标 → 解释，形成主链。先枚举全部参数会使工作失去优先级；先确定瓶颈假设，再决定模型深度。

## 2 正常实验链

| 步骤 | 执行方 | 输入 → 输出 | 失败时保留 |
| --- | --- | --- | --- |
| 定义与解析 | configuration | 原始配置 → 有效配置/来源/哈希 | 错误路径与覆盖链 |
| 装配和能力检查 | evaluation + 硬件模块 | 配置 → 实例/HardwareSpec | 缺失能力与结构约束 |
| 负载准备 | workloads | profile/输入 → WorkloadSpec/参考 | 形状与数据校验信息 |
| 映射/导出 | compiler | 语义/能力 → 放置与执行计划 | 不可行约束与搜索预算 |
| 派发/执行 | runtime + simulator + 组件 | 计划/初态 → 输出/计数器 | 状态、等待链、最后事件 |
| 比对与归因 | evaluation | 输出/指标 → 验证和瓶颈解释 | 容差、差异与统计边界 |
| 提交记录 | artifacts | 所有产物 → 终态 manifest | 缺失产物和中断标记 |

UI 和 CLI 调用同一链条。单次实验可以只执行到结构检查或解析估计，但结果必须标明停在哪层，不能默认表示事件仿真成功。

## 3 修改参数的链条

编辑草稿 → 显示直接值差异 → 重新计算派生量 → 校验跨字段约束 → 检查受影响能力/成本 → 决定计划处理方式 → 冻结新配置 → 新 run。历史配置与结果不可原地更新。

例如改变 `adc_count`：直接影响转换并行与面积；可能影响读出布线和能量模型；改变资源能力和外围服务时间；使相关映射/调度成本失效；最终影响等待、功耗和温度。若无法用现有成本表描述新增 ADC 组织，必须标记估计缺口。

## 4 两种对比协议

| 协议 | 保持内容 | 更新内容 | 可回答的问题 |
| --- | --- | --- | --- |
| 固定映射 Fixed Mapping | 分片、放置、切块与静态策略 | 能力校验、成本、配置绑定、实际执行 | 某个硬件参数的局部影响 |
| 重新映射 Remapping | 工作语义、质量、搜索预算口径 | 切块、放置、缓冲、计划 | 硬件与软件协同后的可实现收益 |

新硬件不支持旧映射时，固定映射候选标不可行；不能偷偷修改切块再称固定映射。重新映射比较需控制优化预算，否则更长搜索时间可能成为隐藏优势。

## 5 分情况选择工程链

架构上限研究：结构配置 → 工作量/流量推导 → 容量与下界 → 灵敏度。无需一开始实现完整 CPU 或 GPU。

微架构研究：固定小负载 → 独立功能参考 → 单资源手算 → 冲突与重叠 → 代表性图。只对能改变结论的队列、bank、流水线增加精度。

系统/集群研究：校准设备摘要 → 节点数据路径 → NIC/fabric 竞争 → 并行和 collective → 扩展曲线。设备摘要的内部误差单独声明。

CIM/3D 研究：编码与数值 → 阵列/外围 → 存储/互连 → 映射 → 精度/性能/能量 → 热与校准。权重编程和热反馈是否进入测量窗口必须明确。

## 6 校准与误差修正链

观测数据 → 对齐工作条件/测量边界 → 分离参数误差和漏建行为 → 训练/验证划分 → 拟合或扩充模型 → 记录残差/适用域 → 发布新模型版本 → 重跑受影响实验。

不能用一个全局利用率系数吸收所有争用和映射错误。若残差随请求规模、温度或路径系统性变化，优先检查结构遗漏。校准参数改善训练点拟合不等于提高域外可信度。

## 7 开发提交与文档维护

新需求先确定状态所有者和公共对象，再修改模块设计、参数定义及实现；验证包括正例和关键非法路径。文档、示例、结构清单与代码同提交。涉及公共语义的变化记录架构决策和版本迁移。

阶段 A 维护目录与规范，B/C 实现最小闭环，D 再做扫描与界面，E 扩展异构和集群，F 针对敏感模块校准。每个阶段的门槛见[验证规范](../architecture/validation.md)。先实现能验证的窄路径，再扩大组合范围。

## 8 运行重用

Replay 用冻结输入重建新 run；Reanalysis 从旧输出/计数器产生新分析版本；Resume 要求完整兼容检查点。保存规则见[产物规范](../interfaces/artifacts.md)。缓存命中必须依据语义身份和模型版本，不能只看文件名或修改时间。
