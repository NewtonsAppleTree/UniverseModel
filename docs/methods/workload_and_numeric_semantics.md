# 工作负载与数值语义的遗漏检查

## 1 先建立完整工作清单

GEMM/MatVec 适合作为首个闭环，但不能据此认为完整模型已被覆盖。真实任务还可能包含 normalization、softmax、activation、transpose、gather/scatter、embedding、sampling、格式转换和通信规约。某个算子不耗很多 MAC，也可能因串行、访存或启动开销成为瓶颈。

为每个算子记录原始语义、实际 shape、输入输出布局、数值规则、支持资源、lowering 和 fallback。覆盖率至少区分算子种类、调用次数、工作量、数据量与基准时间占比；单一“支持 90% 算子”不足以判断端到端收益。

无法处理的算子在编译时显式报错或走声明的回退路径。回退意味着可能新增 CPU 执行、同步、迁移和重排，不得只在数值参考中执行而让时间模型看不到。

## 2 四种字节量必须分别保存

| 量 | 英文 | 用途 |
| --- | --- | --- |
| 语义有效数据 | Logical Bytes | 工作量与算法级算术强度 |
| 实际分配数据 | Allocated Bytes | 对齐、padding、副本、scale/索引与峰值容量 |
| 某存储边界访问量 | Memory Traffic Bytes | 重读、写回、页/行粒度与缓存行为 |
| 某链路传输量 | Wire Bytes | packet/header、编码和重传覆盖范围 |

同一张量可能具有不同的四个数。每个计数器标明边界、方向、payload/协议口径和是否包含重传；转换关系必须有依据，不能用一个 tensor.nbytes 代替全部流量。

布局不是简单字符串标签。至少明确维度顺序、stride、blocking、padding、packing、alignment、scale/zero-point 的分组与位置；跨设备不兼容时，layout conversion 是显式操作或已覆盖的融合阶段。

缓存命中减少某一边界流量，但不消除所有访存。显式管理 SRAM、自动 cache、统一虚拟地址和一致性内存分别建模；需要 TLB/page migration/IOMMU 时在 systemmodel 的地址路径细化，不把连接协议自动解释为已命中或零翻译成本。

## 3 稀疏与压缩的收益有前提

稀疏度描述统计比例，稀疏格式描述如何定位非零，执行机制决定能否跳过。结构化 2:4、block sparse 与任意非零分布需要不同能力；乘数为零不代表硬件没有读取或发射该乘法。

忽略对齐的 CSR 大小可估为 `D_bits = nnz × (value_bits + column_index_bits) + (row_count + 1) × row_pointer_bits`。当索引开销、负载不均或块填充很大时，数据量和执行时间的下降会远小于零比例。

压缩链为压缩/打包 → 存储/传输 → 解压/解码 → 消费。记录压缩粒度、输出长度分布、解码吞吐、临时空间和质量；不能同时使用压缩容量与无解码成本的峰值计算。若压缩长度取决于数据，保存数据来源或确定的长度轨迹。

## 4 动态工作量与软件反馈

动态 shape、MoE 路由、early exit、batching 和预取使实际图依赖输入与执行状态。固定图可展开依赖；动态部分需要明确的条件节点、有限循环或 runtime 生成规则，不在编译器中悄悄使用运行时未知答案。

Trace replay 适合在固定外部需求下比较架构。若新策略改变 batch、cache hit、token 调度或路由，旧轨迹不再代表相同闭环。此时需要生成器/策略模型与资源事件互动，或明确报告“条件于给定轨迹”的结果。

输入随机性、器件随机性与调度随机性使用独立来源。采样 trace 或绘图不能推进目标误差模型的随机序列。

## 5 推理的持久状态

推理需区分模型权重、KV cache、当前激活、预取缓冲、通信工作区和运行时元数据。prefill 与 decode 的 shape、复用和延迟要求不同，应分段统计并保留共享资源竞争。

在所有层维度相同且 KV 使用统一精度的理想条件下，未分片的 KV 有效字节为 `D_KV = 2 × L × H_kv × d_head × (b_kv/8) × Σ_i T_i`。2 表示 K/V，L 为层数，H_kv 为 KV head 数，T_i 为每个活跃请求保留的 token 数。GQA/MQA 用 KV head 数，不用 query head 数代替。

实际分配还包括 page/block padding、量化 scale、碎片和副本。分片、滑窗、压缩、prefix sharing 及各层不同维度需要相应求和/引用规则；共享 prefix 的物理副本只计一次。缓存驻留随接纳、生成、淘汰和释放改变，不能只看平均序列长度。

Speculative decoding、beam search、分离 prefill/decode 等只在研究时启用，但接口需能表达候选分支、接受/丢弃工作及状态迁移。未被用户看到的工作仍可能消耗计算、存储和网络资源。

## 6 训练的更新与重计算

训练需要前向、反向、梯度累加、规约和优化器更新的完整数据链。权重、master copy、gradient、optimizer state 与 checkpoint/recomputation 依算法和精度而变，不能给所有训练任务套一个固定内存倍率。

梯度累加步数会改变通信频率和活跃状态；activation recomputation 以额外计算换内存；流水调度影响激活生命周期。改变这些策略时保存计算总量与通信总量，避免只报告容量下降。

CIM 训练/频繁权重更新还要计编程、验证、重校准和更新粒度。推理的驻留权重成本不能无条件搬到训练；是否值得 CIM，应在相同质量与更新频率下比较。

## 7 数值规则必须落到操作链

精度至少分输入、权重、乘积、累加、存储和输出。声明 scale/zero-point、rounding、saturation、溢出、denormal 和 reduction order；INT8、FP8、BF16 的“8/16 位”并不意味着相同语义或成本。

量化/反量化和误差补偿必须在编译计划中可见，或作为已声明的融合操作覆盖。成本模型和功能模型使用同一量化配置；不能用高精度输出验证低精度时序，却省略实现所需的数值变换。

整体质量先设约束，再比较性能。逐元素误差用于局部验证，模型任务质量用于端到端有效性；局部 RMSE 小不保证任务质量满足要求，单个输入通过也不覆盖所有动态分布。

## 8 CIM 误差的时间和空间结构

| 误差来源 | 可能的状态尺度 | 需要保留的依赖 |
| --- | --- | --- |
| 器件/工艺固定差异 | 某芯片、阵列或单元的一次制造实例 | 同一实例多次读取的相关性 |
| 编程误差 | 每次权重写入后 | 编程算法、写入次数、验证策略 |
| 读出噪声 | 每次访问或采样 | 带宽、转换条件与空间相关性 |
| 漂移/保持 | 从编程时刻起随时间变化 | 权重年龄、温度、刷新与校准 |
| 饱和和非线性 | 输入分布及阵列工作点 | 动态范围、激活组合和外围设置 |

不应每次请求都重新抽取“固定器件差异”，也不应只在启动时抽取全部读噪声。是否采用独立、高斯或线性模型由来源决定；没有数据时标为假设并检查敏感性。

校准是一项有频率、服务中断、存储与能量代价的策略。热、权重年龄和误差若相互反馈，应保存时间状态；不能以一个恒定 error_std 代表所有情形。

## 9 首次实现的取舍

首个闭环只需一个明确布局/精度的 MatVec 或 GEMM、显式搬运、独立参考和完整计数。接口先保留上述身份和边界；其他算子、动态图、cache/TLB 和复杂误差按场景加入。暂未覆盖的行为出现在结果覆盖声明中，不能自动采用最有利假设。
