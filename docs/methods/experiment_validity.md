# 实验有效性与证据设计

## 1 把结论写成有条件的命题

一个实验先冻结目标问题、工作负载分布、质量门槛、可修改变量、物理预算、初始状态与测量范围。结论应说明在什么条件下比较哪两类方案；“CIM 更节能”“卡数增加后扩展良好”不是足够具体的验收目标。

执行成功、功能通过、性能覆盖完整和成本可信分别记录。建议结果至少有 execution_status、validation_status、coverage 与 calibration_scope；缺少其中一项不自动等于失败，也不自动允许作完整结论。

## 2 开环与闭环负载回答不同问题

Open-loop 按外部时间表生成到达，慢设备仍会继续收到请求，能暴露排队与过载。Closed-loop 由固定客户端/并发数在收到完成后提交下一项，到达率会随系统速度变化，适合研究固定并发吞吐。

不能用闭环结果声称系统在同样外部到达率下拥有较低尾延迟。保存计划到达时间、实际接纳时间和拒绝/丢弃数量；测试工具自身跟不上到达节奏时，应报告生成器限制，不能把少生成的请求当作系统性能改善。

Little 定律的平均值不能替代突发、长尾和批处理行为。Poisson 到达是可选假设；真实服务的 burst、长度相关性与租户混合可能改变结论。

## 3 推理指标的时间与分母

| 指标 | 计算范围 | 必须明确 |
| --- | --- | --- |
| Queue Delay | 开始被服务减实际到达 | 是否包含 admission/外部队列 |
| TTFT | 首个输出 token 时间减请求到达 | prefill、排队和输入搬运 |
| TPOT | 多 token 请求的首末 token 时间差除以间隔数 | 单输出 token 时不定义；请求均值与全局均值不同 |
| Inter-token Latency | 相邻输出 token 的时间差 | 分位数取样对象是间隔还是请求 |
| Throughput | 完成请求/有效输出 token 除以时间 | 输入/输出 token、拒绝项和测量窗口 |
| Goodput | 满足约定质量及 SLO 的有效工作除以时间 | SLO 条件、工作单位与完整计数 |

超时或排队中未完成的请求不能悄悄消失。固定到达窗口后的 drain、固定完成窗口或截尾观测采用不同协议；保存未完成队列与统计规则。只统计完成的短请求，会让过载系统看起来延迟更好。

平均 TPOT 掩盖长间隔；增加 batch 可能提高吞吐并恶化 TTFT。方案对比应同时显示吞吐、延迟分布和服务成功比例，而非只取最有利指标。

## 4 初始状态和测量窗口

Cold start、warm start 与 steady state 分开。权重装载、CIM 编程/校准、cache 填充、连接建立和编译是否计入 ROI（Region of Interest）由研究问题决定；即使排除，也保存初始化方式与成本。

预热结束后只重置统计计数器，不应无意复位 cache、温度或器件年龄。相反，研究冷启动时应显式重新初始化目标状态，而不是继承上一候选的有利状态。

记录 ROI 开始前已在途操作及其计费方式：按操作归属累计、按时间积分截取，或等待排空再开始。跨边界操作不能在某指标里全计、另一指标里全不计而没有说明。

## 5 不同来源的随机性分别管理

工作负载抽样、制造差异、CIM 读噪声、路由/调度和观测采样各有独立随机流。保存算法、版本、seed 与子流映射；更换模型版本或对象生成顺序时，seed 相同未必生成同一情景。

比较策略时可采用配对输入或 common random numbers，以降低无关方差；配对必须对应同一个外部情景。不同架构的器件数量和物理单元不同，不能仅用同一个全局 RNG 就声称器件误差已公平配对。

制造差异在一次制造实例内保持固定，再对实例做重复；读噪声在访问层抽样。置信区间采用与采样单位匹配的方法；同一请求内的 token 或同一芯片内的重复读通常不是独立制造样本。

## 6 校准参数可能无法被识别

若简化时延模型为 `T(n)=α+n/B`，只有一个 n 的总时间，就无法唯一确定启动延迟 α 与带宽 B。应在同一路径、无争用、相同条件下改变消息大小，并用留出的大小或其他负载验证。协议切换、缓存变化和拥塞会使该线性模型失效，需要分段或增加机制。

同理，一条总能量曲线不一定能分离阵列、ADC、buffer 与泄漏；一个全局利用率参数可能同时吸收映射空洞与漏建带宽。拟合好总值不代表解释正确。

校准前设计可区分假设的 microbenchmark：改变一个可控输入，观察预期机制。参数不确定性、测量噪声和结构性模型误差分别报告；不能无限增大误差条掩盖系统性偏差。

## 7 搜索中的比较偏差

固定硬件比较映射、固定映射比较硬件、重新映射比较协同收益，采用不同实验组。优化预算、合法化策略、启发式版本和随机次数保持可比较，不能给一个候选更多搜索时间而不记录。

从大量有噪候选中选最优者会产生选择偏差。搜索使用训练/探索样本，最终候选用留出的负载或独立重复复核；保存失败、超时和不可行候选。只保留成功且快的点会扭曲 Pareto 集。

负载集合的权重也影响推荐。至少报告逐负载结果与声明的汇总权重；不能把一次长任务和一次短任务的延迟直接平均后解释为业务总收益。可行域改变，例如旧设备装不下模型，应把容量收益与速度收益分别说明。

## 8 归因需要证据链

指标变化 → 哪条临界依赖或哪项需求变化 → 哪个共享资源等待变化 → 哪项参数/放置/策略导致变化。每条关键边保留关联 ID、时间/字节边界与模型来源。

各操作等待时间相加不等于总延迟；多个瓶颈可以重叠。排队原因统计可多标签，但汇总成互斥时间分解时必须定义分配规则。utilization 高也不证明资源是瓶颈，可能在执行本可消除的多余工作。

可采用受控干预核对假设：保留映射，仅放宽某资源，查看结果是否按预期改善；理想无限资源只作为上界诊断，不是可实现候选。对照不能同时偷偷改变成本和工作量。

## 9 验证工具本身

独立参考验证数值；手算夹具验证时间/资源；变形关系验证应当不变的语义。例如仅重命名资源 ID 不应改变已规定公平策略下的统计分布，关闭 trace 不应改变输出，改变显示单位不应改变物理估计。

这些关系都带前提：增加 buffer 不保证所有策略下延迟单调下降，改变通信规约顺序也不保证浮点逐位一致。测试应检查物理/语义约束，不能把直觉当普适定理。

大规模结果至少保存核心计数器、coverage、输入/初态/计划/模型标识、ROI、随机方案与失败摘要。详细 trace 可分层保留；重分析能回答什么取决于保存了什么，不能从总时间恢复未记录的因果细节。
