# configuration：参数定义、组合与冻结

## 核心与状态

最重要的是一次实验只有一套明确的有效参数。configuration 依赖 contracts，负责参数定义、解析、派生、约束和迁移；config 目录仅存文件。编辑草稿可变，`ResolvedConfig` 一旦交给实验就不可变，修改生成新 revision。

`definitions` 定义字段及元数据，`resolution` 处理模板/实例与覆盖，`validation` 处理局部及跨字段约束，`migration` 转换历史版本。硬件能力约束通过公共描述传入，不反向导入 chipmodel。

## 参数定义与来源

| 元数据 | 用途 | 示例 |
| --- | --- | --- |
| 名称、英文术语、单位、类型 | 保证可读与可计算 | `adc_count`，整数，无量纲 |
| scope、owner、instance_id | 区分模板和实例 | 单 Tile，而非全部 Die 总数 |
| role、default、range、enum | 区分可编辑、派生、必填 | 带宽可由 lane/rate 派生 |
| depends_on、expression_version | 构造派生依赖图 | 峰值吞吐依赖引擎数、MAC/周期、频率 |
| constraints、required_if | 联动验证和条件显示 | 模拟 CIM 才要求 ADC 参数 |
| source、conditions、uncertainty | 保留参数依据 | 手册版本、工作电压、区间 |
| exposure、group、help | 为 CLI/UI 共享展示规则 | 常用/高级/校准字段 |

必填但未知的物理参数应保持 unknown，并阻止需要它的计算；不填入看似合理的默认值。架构探索假设、来源数据、校准拟合值和派生量分别标记。

## 解析与依赖逻辑

建议覆盖顺序为显式 schema 默认 → 组件模板 → 架构实例 → 实验覆盖 → 显式调用覆盖。每个有效值保留获胜来源与被覆盖链；列表默认整体替换，按 ID 合并必须由字段规则声明，不能猜测。

解析步骤：装载与版本检查 → 展开引用 → 生成实例 ID → 应用覆盖 → 单位规范化 → 拓扑排序计算派生量 → 跨字段校验 → 构造依赖解释 → 规范化哈希与冻结。继承环和派生环均报错；删除字段与 null 的含义分别定义。

原生控制量与派生结果不能同时独立编辑。例如以 `lane_count`、`rate`、`efficiency` 推导 bandwidth 时，直接填 bandwidth 必须切换到“实测有效带宽”模型并声明适用条件，不能让两个值冲突。模型选择也是配置的一部分。

## 用户修改与可视化

UI 读取同一字段定义生成表单、单位提示、范围和条件显示；修改草稿后展示：直接改变值 → 受影响派生值 → 约束结果 → 需要失效的计划/成本/结果缓存。实例编辑默认只影响该实例，修改模板时显示所有受影响实例。

配置应支持文本与表单往返、revision diff、固定基线、保存方案、参数扫描和导出有效配置。不能从 UI 直接修改正在运行组件的状态。动态 DVFS 等运行中策略需作为 runtime/硬件事件建模，不能冒充普通配置热更新。

## 场景、优化与验证

小实验可用单文件；多层架构用组件模板和实例引用；扫描使用受约束变量集合，拒绝无条件笛卡尔积。先增加缓存、端口、Die 等离散结构，再检查容量、面积、带宽与热条件，派生量不加入独立搜索维度。

验证重点是覆盖确定性、单位换算、错误定位、派生环和约束反例。保存原始配置、有效配置、覆盖来源、参数定义版本和全部派生公式版本。公式与来源方法见[参数与数学方法](../../docs/methods/parameters_and_math.md)。

## 工作条件与未知值

工艺、电压、频率、温度、精度及几何构成相互约束的工作条件，不能把不同来源的最佳点任意组合。unknown、disabled、真实零值、unsupported 和 out_of_domain 分开；派生量中的未知状态显式传播。配置/计划/运行/分析的缓存依赖分别定义，详见[模型组合](../../docs/architecture/model_composition.md)。
