# RTL 接入：文档与接口规范

**当前阶段：仅文档。已实现 RTL Unit 数量为 0。** 本目录建立未来 Verilog/SystemVerilog 实现的职责、接口、模型映射及证据要求。本轮不包含 HDL、Testbench、断言代码、工具适配器、构建脚本或自动化流水线，也不启动后续实现包。能力状态统一见 [STATUS](../docs/STATUS.md)。

遵循[项目使命](../PROJECT_MISSION.md)：RTL用于回答具体架构机制的数值、周期或实现问题，支持AI与软硬件协同设计；当前不以流片为交付目标。文档完成不表示已通过RTL仿真、综合或物理验证。

## 目录与状态

当前只有本页、UNITS和`docs/`下的Markdown。`rtl/`是独立文档入口，暂不注册为第14个Python模块，不修改[现有依赖清单](../docs/architecture/modules.json)或Python打包范围；`evaluation`、`costmodel`等现有模块仍按原依赖调用。后续实现通过显式数据/文件/工具边界接入，软件依赖图与硬件实例图分别维护。

以下职责仅为后续目录约定，本轮不创建空实现目录：

| 候选位置 | 将来承担的职责 |
| --- | --- |
| `common/`、`compute/` | FIFO、流水线、整数计算、CIM数字外围 |
| `memory/`、`control/` | 存储接口/封装、局部搬运与控制状态 |
| `tops/` | 独立小型组合及实例连接 |
| `tb/`、`formal/` | 测试驱动/行为模型与可检验性质 |
| `constraints/` | 明确来源的时钟、时序及实现约束 |

仿真日志、波形和工具生成物将保存到独立`.build/`或实验产物目录。模拟器、综合器、库和版本由未来具体实验选择；工具存在于电脑中不等于本模块已经接入。

本轮完成条件：接口含义可独立阅读；明确哪些字段尚待具体Unit定义；已有模型、依赖、CI设置保持原状态；模型规则、结构和链接检查通过。下一轮若仍仅讨论规范，继续维护文档，不因候选计划自动进入HDL开发。
