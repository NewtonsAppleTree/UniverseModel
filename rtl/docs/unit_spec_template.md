# 单元规格模板（文档阶段）

本文件是一份填写约定，**不是已完成Unit的规格或实现**。后续选定具体研究任务时复制所需内容到该Unit文档；明确标记不适用项及理由。关键项为“待定”时只能继续设计讨论，不能声称接口已具备实现/验收条件。

语义维护源为[接口](interfaces.md)、[模型映射](model_mapping.md)和[验证](verification.md)，模板引用这些规则，避免复制维护多套定义。

## 1 研究什么

| 项目 | 填写要求 |
| --- | --- |
| Unit / 语义 / 实现版本 | 具名身份、文档版本、未来实现版本；与resource_id分别记录 |
| 研究问题与机制 | 需要检验的因果关系，或该单元服务的具体基础设施需求 |
| 基线与候选 | 固定什么、改变什么、何种条件下可能无收益或不可行 |
| 可观察结果 | 数值/质量、工作量、周期、容量或物理指标及口径 |
| 当前状态 | 文档／实现中／功能验证／周期证据／特征化；每项附实际证据，不能只给一个笼统“完成” |

## 2 怎样建模

| 项目 | 必须明确的内容 |
| --- | --- |
| 功能 | 输入到输出数学关系、操作粒度、空任务、非法操作及副作用 |
| 数值 | 输入/中间/输出位宽与符号，乘加/归约顺序，移位、舍入、溢出、异常 |
| 参数 | 名称、含义、单位、合法域、默认值是否存在、关系及来源；设计输入/派生量/状态/观测分开 |
| 数据布局 | shape/轴/stride、packing、端序、byte/element/beat转换和尾部掩码 |
| 资源归属 | resource_id、owner、层级映射、唯一容量/端口，摘要或内部计量选择 |
| 端口与profile | 方向、payload/sideband位定义、版本、采用基础profile的哪些规则及完整差异 |
| 时钟与复位 | 采样、域、频率条件、复位极性/同步性、初态、取消、存储保留与epoch隔离 |
| 接纳与响应 | ready/valid、每拍/每请求关系、按序/乱序、在途上限、错误和超时 |
| 完成与可见性 | 接纳/内部完成/首次呈现/取走、源释放、写提交、可见域和复位副作用 |
| 局部状态 | 必要队列/指针/累加状态；谁更新；重置或恢复的范围 |
| 时间模型 | L/II的起止边沿、item及lane含义、无阻塞条件、等待与填充/排空 |
| 组合条件 | 相邻Unit的容量/时钟/格式兼容，适配器引入的工作和成本 |
| 专业边界 | SRAM同址规则、CIM行为模型等适用项；明确不覆盖的机制 |

## 3 如何证明

| 项目 | 填写要求 |
| --- | --- |
| 独立参考 | 原理/来源、入口、支持域、容差或位精确规则；说明独立于被测实现的部分 |
| 必验案例 | 手算、极值、尾部、参数替换、背压、容量、复位、顺序/守恒、失败 |
| 性质与进展条件 | 安全性质、活性所需环境条件、形式验证范围（如采用） |
| 工作量与质量 | 逻辑/实际操作、padding/转换/搬运、任务质量门槛及比较预算 |
| 周期与物理证据 | 时钟/统计窗口、工具/版本、约束/库/PVT、适用范围及未知项 |
| 来源与保存 | 设计/驱动/参考/输入的完整身份，产物清单、失败记录、回读与重跑区分 |
| 完成标准 | 与研究主张对应的可检验条件，未完成项及不适用项分别列出 |

首个数字单元可先选择现有INT8/INT64 Linear语义支持域，但必须另填请求打包、存储、位宽和时序，不能从Python类名推断实际电路。当前没有选定或启动该单元实现。
