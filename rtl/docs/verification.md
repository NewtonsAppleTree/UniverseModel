# RTL 验证、来源与交付门槛

**当前只交付规范，以下RTL验证均未执行。** 本轮仅检查文档范围、链接、规则与既有工作区保护。后续证据按[项目使命](../../PROJECT_MISSION.md)和[实验有效性](../../docs/methods/experiment_validity.md)选择深度；以[接口](interfaces.md)和[模型映射](model_mapping.md)定义被验证的行为。

## 1 证据分层

| 研究主张 | 应有证据 | 不能从该证据推导什么 |
| --- | --- | --- |
| 文档与配置含义明确 | 完整Unit规格、单位/范围、语义审查和链接检查 | RTL存在、功能通过、周期或物理性能 |
| 数字功能正确 | 相同输入的独立参考、逐事务配对、位宽/溢出/复位/背压边界 | 数据集质量、完整吞吐或物理可行性 |
| 某时序/缓冲机制有效 | 明确初态、到达/ready、有限容量、真实接口轨迹、性质与等待归因 | 其他流量分布或不同实现上的普遍结论 |
| AI质量满足要求 | workloads中的实际任务、数据划分、数值方法、质量门槛和比较预算 | 仅凭一个MAC或小矩阵对照推断泛化质量 |
| 面积/时序/能效可行 | 具名实现、库/PVT、工具/约束/活动、报告及覆盖/误差 | 综合成功等同完整PPA或流片签核 |

通过编译、进程退出0、波形存在或模型自报PASS均不足以单独证明正确。参考应在实现机制上独立：例如整数点积用显式数学累加，FIFO用独立顺序队列，SRAM值用独立字节存储；不调用被测计算生成期望值。

## 2 将来每个单元的最小验证矩阵

| 范围 | 至少考虑的输入或状态 | 独立判据 |
| --- | --- | --- |
| 数值 | 零、正负极值、尾块、不同K、抵消、边界溢出 | 与声明的每步/最终数值规则一致，误差与容差有依据 |
| 接纳与顺序 | 连续/间断valid、多笔在途、重复数据但不同请求身份 | 每个已接纳请求仅对应一次响应或取消，按所选profile顺序 |
| 背压 | 长时间不ready、随机阻塞、首次呈现即阻塞 | 有效载荷稳定、无丢失/重复，不能把等待周期算新请求 |
| 有限容量 | 空/满、深度1、同时入出、最大合法在途量 | 容量不越界、符合显式同时入出规则、守恒式成立 |
| 复位 | 初始、计算中、输出阻塞中、连续多周期复位 | 旧请求只取消一次、无旧epoch响应、有效状态正确；存储副作用另核对 |
| 存储 | 首末合法地址、越界、掩码、同地址读写、多个端口 | 逐字节效果、顺序/冲突规则、ack与局部可见性一致 |
| 参数替换 | 小/大合法位宽、lane/容量变化、非法格式组合 | 支持域清晰；非法参数显式拒绝，不能静默截断 |
| L/II及周期口径 | 无阻塞、端口限制、尾组、输出阻塞 | 起止边沿一致，必要下界与实际时间分别解释 |
| 错误与终止 | 合法错误响应、协议违例、工具失败、超时、截断 | 失败保留原因/在途/副作用；未结束工作不生成完整指标 |

X/Z检测应覆盖复位结束后被采样的控制和有效payload；无效payload不要求伪造零。对于采用二态执行的工具，需记录其盲区，不能宣称已覆盖四态未知传播；必要时使用四态工具或独立性质补证据。

若采用形式验证，应保存设计/性质版本、环境假设、参数、引擎、范围/深度、证明状态及反例。对任意背压的安全性与带“消费者最终就绪”条件的活性分开；有界搜索未发现反例不等于无界证明。当前没有断言代码、形式脚本或已证明性质。

## 3 同任务比较与证据解释

主比较固定任务、数值规则、输入/初态、资源预算、时钟、到达/ready过程及统计窗口。增加lane/端口/容量或改变频率属于显式资源干预；映射/位宽/截断改变时同时核对额外工作和质量，保留无收益与不可行案例。

可确定的周期实验记录确切输入与调度即可；依赖随机流量、误差或到达的结论需保存种子及多次运行/统计口径。宿主编译、工具运行与搜索耗时只作为实验开销，绝不代替目标周期或秒数。

未知时延、能耗或面积保留未知原因；仅部分服务已覆盖时报告覆盖范围及必要下界。不得用下界当实际执行窗口计算漏电，也不得把复位取消或失败请求从吞吐分母中默默删除。

## 4 未来运行记录与产物接口

复用[ExperimentSpec/Metric/RunRecord](../../contracts/results/experiment.py)及[工程框架](../../ENGINEERING_FRAMEWORK.md)，当前不新增这些对象的字段或枚举。HDL工具和比较逻辑仍需未来适配器实现。

| 内容 | 应保留的来源 |
| --- | --- |
| 设计与驱动 | HDL、include/generated文件、宏、参数、Testbench/断言、驱动及参考的版本和原始字节哈希 |
| 输入与初态 | 任务/数据身份、实际输入或可恢复引用、seed、复位、存储初态及ready轨迹 |
| 执行环境 | 工具完整版本、构建选项、显式命令、环境依赖和退出状态 |
| 实现约束 | clock/reset、SDC或对应约束、库/宏/PVT、未解析blackbox和时序例外 |
| 结果与覆盖 | 输出、对照误差、计数/边沿、失败/超时、日志、必要波形、综合/时序报告和未知项 |

当前源码快照工具面向Python/config/pyproject；未来接入RTL时须扩展或独立提供HDL及其依赖的完整清单，不能仅复用Python源码哈希声称RTL来源已绑定。配置只承载数据；工具选项由具名适配器校验，不从配置运行任意脚本、动态import或公式。

已有实验mode为functional/analytical/static_schedule/event。将来仅做数值对照可用functional；只有实际执行并保存目标事件/边沿语义时，才采用event及simulated指标；综合/条件估算按其证据标为analytical/estimated。cycle指标必须附clock_domain。文档中“RTL”是后端类型，不是已实现的新mode。

RunRecord的succeeded仅说明该次执行/记录有效，还必须保存独立验证结论；失败保留diagnostic。文档的未实现/未运行状态不能伪装成一条succeeded记录。协议内的预期error响应与宿主工具失败分别解释，不能因两者都含“error”而混淆测试成败。

大波形、网表或数组按具名文件及完整性清单保存；当前小数据bundle不会自动把任意外部文件纳入哈希，未来适配器须明确所有产物引用。旧运行目录不覆盖；检查原始文件完整性、语义一致性及来源绑定。回读不能重新仿真来替代历史结果，重跑生成新的尝试身份。
