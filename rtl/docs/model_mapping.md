# Python 模型与 RTL 的映射约定

**状态：文档设计，无适配器或RTL实现。** 接口事件以[接口规范](interfaces.md)为维护源；参数先查[架构参数清单](../../ARCHITECTURE_PARAMETERS.md)，Python实际字段继续以代码及[chipmodel UNITS](../../chipmodel/UNITS.md)为准。

## 1 一次映射必须保存什么

| 内容 | 要求 |
| --- | --- |
| 数学任务 | operation、shape/轴、输入/权重/输出格式、累加与舍入、输入数据及版本；来自workloads或独立直接输入 |
| 具体实现 | Unit/profile/实现版本、资源与RTL层级映射、合法参数域、存储和时钟边界 |
| 驱动条件 | 初态、复位、输入到达、输出ready、随机种子、有限容量及停止策略 |
| 分析口径 | Python入口/版本、每个work item含义、L/II来源、假设与未知成本 |
| 对照结果 | 逐事务结果/状态、工作量、接口边沿、误差/容差及来源；功能与时间分列 |

不能因为两侧都叫MAC或SRAM就推定等价。一个Python模型允许的参数域可能比某RTL实现更宽；不支持的交集之外请求应明确拒绝。改变数据格式或映射时保留原始任务及转换工作，不根据硬件能力反向改写任务要求。

## 2 数值与布局

整数必须明确二进制补码/无符号、乘法结果宽度、符号扩展、移位语义、累加顺序和输出截取。逐次wrap/saturate与最后一次wrap/saturate通常不等价；需要有限位宽中间行为时补对应独立参考，不能直接使用Python无限精度中间量冒充硬件。

以零初值、K个有符号A_BITS×B_BITS整数乘积相加为例，`A_BITS+B_BITS+ceil(log2(K))`是避免累加溢出的保守充分位宽，K≥1；不是最小位宽定理。含初始累加值、偏置或额外加项时须重新推导范围。若选择INT8输入和INT64输出对照现有Linear参考，遵循[LinearSpec](../../contracts/workload/linear.py)的`K·128·128 ≤ 2^63−1`支持域；窄累加器、量化输出或饱和属于新增语义。

浮点要分别说明float16/bfloat16/float32/float64、FMA是否融合、每步舍入、非正规数、NaN/Inf及异常策略。现有[MacArray](../../chipmodel/compute/npu/mac.py)的格式能力声明不执行数值计算；黄金值应来自[workloads/reference](../../workloads/reference/UNITS.md)或有独立来源的参考。

布局记录行/列主序、轴序、stride、字节序、元素/字节/拍对应关系、尾拍掩码及padding。padding可占用传输或发起槽，但不得混成逻辑MAC或有效元素；转换、打包、零填充和回传工作独立计量。地址域变化通过具名映射解释，不把不同backing中相同数值地址当作同一物理位置。

## 3 周期与服务参数

RTL观察边沿以接口的i/j/k为准；内部compute_done、外部首次呈现、消费者取走可能不同。报告L时必须说明是哪对事件，不能把内部寄存器更新时刻与下一采样边沿混用。频率f固定时，周期差Δc换算为`Δc/f`秒；多个时钟域不直接相加cycle。

无阻塞、独立工作、充分在途容量、等价lane等条件下，[公共流水线](../../chipmodel/common.py)采用`G=ceil(W/P)`和`C=L+(G−1)·II`，空工作另为0。只有当两侧item、发起组、起止时刻及条件完全一致时，才可用RTL轨迹核对C。一次点积请求包含多个MAC，不能将点积响应延迟直接赋给每MAC的L。

归约反馈、端口冲突或背压可能使实际发起间隔大于声明II。固有II须在输入就绪、消费者接收、资源条件明确的协议下测量；含等待的平均吞吐单独报告。目标时钟是约束输入，RTL仿真按该时钟运行不证明电路达到该频率。

Python的必要时间下界可以与同边界RTL执行时间检查条件关系；差值应分解为依赖、等待、填充/排空等已观察工作。不能强求下界等于实际响应时间，也不能用一次实现的测量值覆盖其他参数域的通用模型。

## 4 资源、存储与CIM边界

| 现有模型范围 | RTL接入必须补明的关系 |
| --- | --- |
| SRAM的bank/word/端口事务 | 地址映射、R/W共享、真实读写语义、仲裁与宏类型；静态分析没有证明存储数据值 |
| BufferReservation | 只证明空间预留；FIFO队列、valid、指针、复位和背压需要独立状态语义 |
| DMA的startup/burst/通道服务 | 对应哪些实际状态/拍；源读、通路和目标写是否已包含；未知外存等待不可填零 |
| 数字Tile/Assembly | 同一resource_id与一份容量/端口预算；摘要与内部实现按相同指标互斥选择 |
| CIM数字重建/累加 | 明确ADC码到整数/定点的比例、偏置、差分、舍入、逐级位宽及误差；浮点/有理参考不能自动转为定点电路 |
| CIM模拟阵列/外围 | 模拟部分由具名行为模型/外部工具给出；保持时间、电流电压、噪声及编程成本来源单独保留 |

组合时选择完整RTL测得服务或对应范围内的Python摘要之一；若只测局部阶段，列明剩余阶段及计量边界。多实例使用一个物理宏/控制器时，该资源仍只登记一次；实例展开不自动增加存储或带宽。

## 5 校准与反向使用证据

未来RTL周期、综合结构和时序报告先作为实验产物进入evaluation，再按验证范围生成有来源的profile供chipmodel/costmodel显式选择。记录参数点、工具/约束、覆盖与误差；保留未参与拟合的参数/工作负载作独立验证，报告失效或无收益条件。

综合门数不是工艺面积；面积报告不证明布线/供电/热可行；有库的STA也要说明互连和约束假设。能量还依赖动作/活动、PVT和观察窗口，不能由周期或面积直接推断。未知指标使用明确未知状态。记录要求及具体验收矩阵见[验证规范](verification.md)。
