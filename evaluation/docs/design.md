# evaluation：实验、校准与设计空间探索

## 核心与依赖

最重要的是在同一问题、约束和证据标准下比较方案。evaluation 是组合入口，可依赖除 ui 外的全部主模块，负责装配和运行编排；不成为硬件或策略状态的第二所有者。

`experiments/runner` 运行单次实验，`sweeps` 生成候选，`analysis` 计算指标与归因，`optimization` 搜索，`calibration` 用观测更新成本/模型依据。校准产生新版本，不原地改变已经运行的模型。

## 输入输出与比较单元

输入为实验问题、负载集合、配置空间、质量和资源限制、比较协议；输出是运行集合、可行性/功能验证、指标、Pareto 集及适用结论。每个结果绑定输入/配置/计划/成本/代码身份。

关键参数为 objectives、constraints、fixed/remap、search budget、seed/repetitions、到达过程、预热/测量区间和校准数据划分。性能差异必须与这些条件一起展示。

## 工作流与数学

问题定义 → 基线校验 → 约束过滤 → 解析筛选 → 编译/映射 → 功能与事件验证 → 指标/误差汇总 → 归因 → 下一批候选。M05/M06 提供上限与下界，M15 提供扩展口径，M16/M17 支持质量和敏感性。

多目标优化保留延迟、能量、面积、质量及风险的 Pareto 关系。先明确约束再谈“最优”；如果目标要加权，记录权重和归一化。固定映射用于局部归因，重新映射用于架构与编译共同收益，两种报告分别生成。

## 分情况选择方法

变量少且离散可用完整枚举；连续低维可用网格/采样；昂贵模型可用贝叶斯或代理模型；混合结构可用分层搜索；有明确线性约束的小映射可用 ILP/CP-SAT。搜索算法不能弥补不可信的成本和漏建瓶颈。

随机执行波动用重复运行评估，参数不确定性用情景/采样评估，二者分开。校准集不用于验证最终准确度。候选排名在合理不确定区间内翻转时，优先补充该参数证据。

## 验证与留存

检查指标边界、失败统计、不可行候选、重映射策略和重复种子。记录有效/失败/取消数量，禁止只汇总成功且更快的子集。保存实验定义、候选生成顺序、预算、运行清单、指标版本和推荐的适用条件。

## 实验依据补充

开环/闭环到达、冷/热初态、跨 ROI 在途工作和未完成请求分别声明；功能验证、成本覆盖与运行状态分别判定。参数校准先检查可识别性，搜索结果用独立样本复核，见[实验有效性](../../docs/methods/experiment_validity.md)。未来实现可使用[六个手算示例](../../docs/methods/design_tradeoff_examples.md)核对边界。
