# compiler：语义保持与资源映射

## 核心与依赖

最重要的是优化后的计划仍然完成同一语义并满足资源约束。compiler 依赖 contracts、costmodel，读取 HardwareSpec；不读取硬件内部状态、不依赖 simulator。输出静态计划，实际时序由 runtime 与资源竞争决定。

## 保留现有结构与阶段职责

| 目录 | 输入 → 输出 | 必须保持 |
| --- | --- | --- |
| src/ir | WorkloadSpec → 内部 IR | dtype、shape、布局、效果与依赖 |
| globalsplit | 图 → 分区/分片候选 | 数据依赖和必要通信 |
| globalsolver | 候选与能力/成本 → 全局放置 | 容量、操作支持和优化目标 |
| tiling | 算子/资源 → tile 与迭代顺序 | 覆盖完整且边界正确 |
| memplan | 数据生命周期 → 区域/地址分配 | 同时活跃容量与别名合法 |
| sched | 操作依赖/资源 → 静态顺序约束 | 因果关系与可执行性 |
| lowering | 高层操作 → 目标操作序列 | 数值和副作用语义 |
| interpret | IR 与输入 → 语义结果 | 与独立参考可比较 |
| export / pipeline | 阶段结果 → 版本化计划 | 哈希绑定与阶段前置条件 |
| lba | 保留目录，待定义其真实算法职责 | 未定义前不进入 pipeline |

这不是固定一次通过顺序。切块、存储规划、放置及成本评估可能迭代；每个 pass 声明输入能力、修改内容及失效的分析结果，避免隐式共享可变全局状态。

## 输入输出与参数

输入包括 WorkloadSpec、HardwareSpec、CostProfile、精度约束和映射策略。输出 PlacementPlan、ExecutionPlan 与可选静态 CommunicationPlan，保存 pass 版本、搜索预算、候选摘要和选择原因。

主要参数为 tile shape、dataflow、布局、融合边界、张量分片、rank 放置、buffer allocation、双缓冲、调度优先级和允许的动态空间。资源数和频率由硬件提供，compiler 不拥有另一套硬件参数。

## 数学方法与逻辑链

用 M09 检查活跃容量，用 M05/M06 估计算术强度和资源下界；将放置变量、容量/连通/操作支持约束建成整数约束，可在小问题上用 ILP/CP-SAT，在大空间采用启发式和分层搜索。解析成本用于筛选，不直接当作实际时序。

异构划分的收益需超过迁移、转换和同步代价。CIM 映射还需权重编码、位切片、外围调度与输出累加。跨节点通信由真实分片推导，不能把每个算子简单分摊到卡数而忽略通信。

## 静态与动态分工

固定 placement、buffer 和依赖属于静态计划；就绪任务在何时提交、动态批处理与实际 collective 进度属于 runtime。编译器可给出策略参数或可选路径，但不能使用未来事件结果。固定映射敏感性实验重新校验计划，在新配置下无效则记为不可行，不自动悄悄重映射。

## 验证与保存

单 pass 使用独立参考或 IR 解释器比较；完整 lowering 同时检查数值、数据位置和副作用。验证不只比较最终数组，还检查非法容量、缺失搬运、数据提前使用等反例。保存输入哈希、最终计划、关键优化决策和编译版本；调试 IR 可按需保留。
