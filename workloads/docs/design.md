# workloads：工作语义、输入与参考

## 核心与边界

最重要的是先定义要完成的工作和允许的误差。workloads 依赖 contracts，拥有任务描述及独立参考；不依赖目标硬件模型。`kernels` 放单算子，`graphs` 放图，`reference` 放参考语义，`profiles` 放代表性形状/到达分布，`datasets` 放数据清单与适用说明。

## 输入输出与参数

输入是任务类型、形状、输入分布和质量要求；输出 WorkloadSpec、DataRef 清单、参考执行规则及工作量统计。关键参数为 batch、sequence length、矩阵维度、dtype、accumulator width、layout、sparsity、任务到达率和输出容差。

稀疏度必须说明结构与分布，不能用一个零比例假定所有零都可跳过。动态形状保存实际取值和分布。推理 prefill/decode 与训练的权重、激活、KV cache、梯度及优化器状态不同，应分别建立 profile。

## 逻辑链与数学

语义 → 实际形状/精度 → 计算量 → 逻辑数据量 → 可供映射的依赖图。GEMM 的逻辑 MAC 数为 M×N×K；若采用一 MAC=两次运算则 op 数为 2MNK，必须统一口径。逻辑数据量不等于实际访存量，后者取决于映射、缓存和重读。

M01/M03/M09/M16 分别支持容量、工作量、生命周期与误差判断。参考输出应独立于 compiler lowering 和目标执行实现，否则二者共享错误时会产生虚假通过。

## 情况、优化与验证

微基准用于分离计算/访存/同步瓶颈，代表性图用于端到端判断，真实 profile 用于检验泛化。小算子最快不代表模型最快；平均 shape 也不能代表长尾请求。

优化评估固定质量要求、输入范围和任务边界。量化、剪枝或算法变化应生成新 workload 版本并报告质量变化，而非只记作硬件参数提升。验证参考边界、形状与输入哈希；保存生成种子、数据版本、工作量口径和容差。

## 完整负载补充

非矩阵算子、格式转换、KV cache、训练状态与更新均可能改变端到端收益。逻辑数据与物理分配/访问/传输分别统计；稀疏比例不自动减少实际发射。具体边界见[工作负载与数值语义](../../docs/methods/workload_and_numeric_semantics.md)，服务到达过程见[实验有效性](../../docs/methods/experiment_validity.md)。
